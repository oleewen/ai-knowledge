# 示例跨系统解决方案

> 读者：**业务与产品**。
> 本文件为 `company/solutions/` 目录结构演示，非真实业务方案。

---

## 1. 背景与目标

### 1.1 业务现状

这是一个跨系统协作场景的结构示例：多个系统共同完成同一条业务链路，业务侧需要在一个视角下看到统一状态与可追溯信息。

### 1.2 存在问题

现状下信息分散在多个系统中，业务人员需要在多个入口之间来回切换，导致排查耗时、协作成本高，且对外口径不一致风险上升。

### 1.3 业务目标

- G-1 将跨系统链路的关键状态聚合为统一视图，业务侧能快速定位“当前在哪里卡住了”。  
- G-2 将对外承诺口径统一到可验证的业务规则，减少解释成本与争议。

### 1.4 业务价值

减少人工对账与沟通往返；提升问题响应速度；降低因口径不一致带来的客户体验波动。

---

## 2. 范围与约束

### 2.1 核心场景

业务人员在一个入口下发起查询，系统返回该业务对象在各系统中的关键状态、时间点与下一步动作建议。

### 2.2 涉及角色

| 用户角色 | 角色描述 | 核心关注点 |
| -------- | -------- | ---------- |
| 业务人员 | 处理业务流转与对外解释 | 状态可见、口径一致 |
| 运营人员 | 跟进处理时效与异常 | 时效、异常定位 |
| 协作方 | 参与链路中某环节处理 | 交接清晰、可追溯 |

### 2.3 范围边界

#### 范围内（In Scope）

- 对单一业务对象提供跨系统关键状态的统一展示与追溯信息。
- 提供与业务规则一致的状态解释与下一步指引。

#### 范围外（Out of Scope）

- 不引入新的业务规则变更；仅对既有规则进行口径统一与呈现。
- 不改变各系统原有处理流程；仅补齐展示与追溯所需的业务字段口径。

#### 成功标准

- 业务人员在单一入口完成状态查询与定位，且能给出一致解释口径。
- 典型问题的定位耗时显著下降（以业务侧可验收口径为准）。

### 2.4 关键约束

#### 业务约束

- 对外口径必须一致；出现冲突时以业务规则优先级与可追溯证据为准。

#### 资源约束

- 以最小改动方式落地，优先覆盖高频链路与高价值对象。

#### 技术约束

- 仅使用业务可读的描述表达“能力限制”，不在正文展开工程实现细节。

#### 交付约束

- 如无外部硬截止，按业务优先级分阶段交付；每阶段可独立验收。

## 3. 影响与冲突

### 3.1 影响面

- 业务人员：入口变更为统一视图，减少多处查询。
- 运营人员：异常定位路径更短，可追溯信息更集中。
- 协作方：需要对关键状态口径达成一致并可追溯。

### 3.2 影响业务能力

| 功能/业务能力 | 影响程度 | 影响类型       | 影响说明 |
| ------------ | -------- | -------------- | -------- |
| 状态查询     | 高       | 口径调整       | 从多入口查询收敛为统一视图 |
| 异常定位     | 中       | 追溯增强       | 提供关键时间点与责任归属提示 |
| 对外解释     | 高       | 承诺一致性提升 | 以统一规则与证据支撑解释口径 |

### 3.3 影响传播路径

```
[状态查询] → [异常定位] → [对外解释] → [跨团队协作]
```

### 3.4 业务冲突

| 冲突编号 | 冲突描述 | 冲突类型                   | 严重程度 | 化解方案 | 化解成本 |
| -------- | -------- | -------------------------- | -------- | -------- | -------- |
| C-1      | 不同系统对同一状态的命名与判定口径不一致 | 规则冲突/流程冲突/数据冲突 | 中       | 统一口径并补齐可追溯证据 | 中 |

## 4. 思路与方案

### 4.1 解决思路

以“业务对象”为中心建立统一视图：对齐关键状态口径、补齐可追溯信息，并用业务可读的方式说明当前状态与下一步动作。

### 4.2 方案对比（如有多种方案）

| 对比维度   | 方案A | 方案B |
| --------  | ----- | ----- |
| 业务匹配度 | 高：统一视图与统一口径 | 中：仍依赖人工对齐口径 |
| 实现复杂度 | 中：需口径与追溯对齐 | 低：仅做文档约定 |
| 影响范围   | 中：涉及多系统协同 | 低：改动较少 |
| 风险程度   | 中：口径收敛需共识 | 中：口径漂移风险仍在 |
| 可扩展性   | 高：可逐步扩覆盖面 | 低：依赖人工维护 |

### 4.3 关键决策

| 决策点 | 推荐方案 | 备选方案 | 选定理由 |
| ------ | -------- | -------- | -------- |
| 统一视图是否引入口径收敛 | 方案A | 方案B | 口径不一致会持续制造争议，统一视图必须以可追溯口径为基础 |
