# 示例应用功能特性

> 读者：需求分析师与产品/架构。路径：`application/features/`。

## 1. 背景目标

### 1.1 需求背景

- 关联需求分析：`application/analysis/ANALYSIS-EXAMPLE.md`
- 本应用先收口申诉的唯一提交通道，并让进度可自助查看。

### 1.2 需求目标

| 目标编号 | 目标描述 |
| -------- | -------- |
| G-1 | 主路径账单可提交申诉并查到进度 |

### 1.3 范围约束

#### 范围与边界

- 范围内：本应用主路径账单的提交通道与进度可见
- 范围外：系统层跨应用编排

#### 假设与约束

- 上游 §6.1 的「里程碑-1」覆盖唯一提交通道与基础进度

#### 研究与分析

- 双单来自旧入口并行；本特性先收主路径

## 2. 功能需求

### 概览

本样例上游 §6.1 的里程碑列写的是「里程碑-1」，此处原样抄入。技能常态写法是 `M{n}（短名）`。

| 需求编号 | 需求名称 | 需求概要 | 优先级 | 所属模块 | 所属里程碑 | 关联目标 |
| -------- | -------- | -------- | ------ | -------- | ---------- | -------- |
| FR-001 | 唯一提交通道 | 主路径账单只从一个入口提交申诉 | P0 | 申诉提交 | 里程碑-1 | G-1 |

### FR-001: 唯一提交通道

**描述**：用户对主路径账单发起申诉时，只走本应用的提交通道，并能看到进度。

**输入**：主路径账单，以及用户发起申诉。

**处理逻辑**：

| 规则编号 | 规则名称 | 触发条件 | 执行逻辑 |
| -------- | -------- | -------- | -------- |
| BR-001 | 单入口 | 同一账单已有进行中的申诉 | 拒绝另开一单，并展示已有进度 |

**业务对象**：

| 业务对象 | 操作类型 | 变更说明 | 一致性 / 时效期望 |
| -------- | -------- | -------- | ----------------- |
| 申诉单 | 新增 | 主路径只保留一单 | 提交后可查进度 |

**输出**：用户看到受理结果和当前进度。

**异常与边界**：非主路径账单不在本 FR 范围。

**验收标准**：

1. 主路径可提交并查进度
2. 双单率可控
