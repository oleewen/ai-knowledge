# 设计原则（sdx-analysis）

验收勾选项见 [quality-checklist.md](quality-checklist.md)；语言规范见 [audience-and-language.md](audience-and-language.md)。

---

## 原则

| 原则 | 要求 |
|------|------|
| 模板驱动 | 严格遵循 [../assets/analysis-template.md](../assets/analysis-template.md) 六章结构；无内容章节标「不适用」或「待补充」，禁止整节空白 |
| 证据优先 | FR、BR、风险须引用解决方案文档与 `knowledge/` 事实，禁止臆测 |
| 业务可读 | 正文（§1–§5 及 §6.1–§6.2）无接口名、表名/字段名、中间件、模块名、协议栈；技术线索仅在 §6.3 并含「待研发确认」 |
| 歧义标注 | 歧义、矛盾、信息缺失须标注为 Q-n，逐一向用户提问，禁止自行假设后继续 |
| 按需加载 | 仅在本轮任务需要时打开文件，禁止通读 `knowledge/**` 或全仓源码 |
| 可追溯 | FR→G-n；BR→FR；MVP→FR；R-n→依赖或影响面；编号连续无断号 |
| 范围清晰 | 仅产出需求分析文档，不涉及 PRD / ADD / 代码 |

**证据引用格式**：

| 证据类型 | 格式 | 示例 |
|---------|------|------|
| 业务目标 | `G-{N}` | `G-1 提升申诉处理效率` |
| 知识库实体 | `{视角}-{ID}` | `BC-001 FeeAppealContext` |
| 文档章节 | `{文件} §{章节}` | `INDEX_GUIDE.md §3.2` |

## 错误处理

| 错误场景 | 处理方式 |
|---------|---------|
| 解决方案文档不存在 | 终止，提示先执行 sdx-solution |
| 解决方案文档结构不完整 | 发出警告，列出缺失章节，基于已有内容继续并标注「基于不完整解决方案，存在分析盲区」 |
| knowledge 目录缺失 | 发出警告，仅基于解决方案文档完成分析，在 §1.3 标注「缺少知识库基线」 |
| 模板文件不存在 | 终止，提示创建 `.agent/skills/sdx-analysis/assets/analysis-template.md` |
| MVP 拆分出现循环依赖 | 终止拆分，输出依赖图，请求用户确认调整方案 |
| 输出目录不存在 | 自动创建 `{DOC_DIR}/analysis/` 目录 |
