# brainstorming 与 sdx-analysis 的衔接（嵌入层）

本文件说明：在 **`/sdx-analysis` 阶段二**如何把 **brainstorming** 的对话节奏嵌入门禁 **G{n}**，并与 Q-n、C/M/S/F 协同。执行阶段二时**建议打开本文**，避免与独立执行 `/brainstorming` 时的默认产物与终态混淆。

---

## 与独立 `/brainstorming` 的差异（须牢记）

| 维度 | 独立 `/brainstorming` | 本技能内嵌（阶段二） |
|------|----------------------|------------------------|
| 主产物 | 常为 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` | 会话 spec：`...-sdx-analysis.md`；终稿：`ANALYSIS-*.md` |
| 正常终态 | 经批准后进入 `writing-plans` 等实现计划 | **Qclose-1** → 阶段三分块定稿；**不**在本会话内以 `writing-plans` 作为默认收尾 |
| HARD-GATE | 以 brainstorming 技能为准 | **仍以 sdx-analysis HARD-GATE 为准**：总确认前默认不写 `{DOC_DIR}/analysis/ANALYSIS-*.md` |

**禁止**：在仅执行 `/sdx-analysis` 的对话中，用「已完成 brainstorming」为由跳过 Gn 收口、门禁标记或 Qclose-1；也**禁止**默认创建 `*-design.md` 替代本会话 spec。

若用户**明确需要**一份独立设计 spec，应**另开会话**执行 `/brainstorming`，再在后续会话用本技能消费其结论。

---

## 嵌入层：何时触发

在阶段二**任意门禁 G{n}** 内，出现以下任一情况，即进入 **brainstorming 式子流程**（可与 Q-n 交替，但须保持「一次只推进一条主线」）：

1. **多套可取舍方案**：同一门禁下存在两条及以上**真实可选**的路径（FR 切分、非功能取舍、MVP 切法、依赖假设、风险应对等），需要用户做取舍。
2. **需要结构化权衡**：不仅缺信息（那是 **Q-n**），而是信息足够但**利弊并存**，需对比后再写入「本门禁结论」。

**不必触发**：仅有一个合理路径、或仅需澄清事实而无方案分叉时，按原有草案 → 确认点 → 收口即可。

---

## G{n} 内「多方案」子流程（推荐顺序）

在**该 G{n} 未收口前**完成：

1. **点名方案**：列出 **2–3 套**（或「维持现状 / 变更 A / 变更 B」）。名称须为**业务语义**（与 [workflow-spec.md](workflow-spec.md) 中 Q-n 要求一致），避免空洞的「方案A/方案B」字样。
2. **利弊与取舍**：每套给出适用条件、成本/风险要点、不适用场景；给出**推荐项及理由**（可被拒绝）。
3. **用户确认**：用本技能**标准四选项**（C/M/S/F）收口本门禁；结论写入 spec 的「本门禁结论」，并注明被选方案及未选方案的搁置理由（若适用）。

与 **Q-n** 的分工：

- **Q-n**：信息不足、歧义、矛盾待澄清 → 每次一题，见 workflow-spec。
- **多方案子流程**：信息已够，但**决策分叉** → 用本节结构；若分叉内仍有事实缺口，先收敛 Q-n，再回到方案对比。

## 与各门禁的典型触发（非穷尽）

| 门禁 | 可能出现的「多套方案」示例 |
|------|---------------------------|
| G1 | 范围叙事不同导致 §1.2 目标优先级排序分叉 |
| G2 | FR 拆分粒度、P0 边界、是否合并/拆分 FR |
| G3 | 非功能取舍（如可用性 vs 交付节奏）、合规口径 |
| G4 | MVP 切法、里程碑多种排法、依赖顺序 |
| G5 | 依赖假设、风险接受 vs 缓释策略 |
| G6 | 附录粒度、对外承诺级别、§6.4 勾选策略（在合规前提下） |

**G2、G4** 常为多方案密集区，但**不限于此**：只要当前 G{n} 的结论依赖方案选择，就应在本门禁内完成对比再收口。

## 与 brainstorming 检查清单的对照（阶段二内）

| brainstorming 要点 | 在 sdx-analysis 中的落点 |
|---------------------|-------------------------|
| 探索项目上下文 | G1 前及回跳后材料不足时补充 |
| 单题澄清 | **Q-n**（workflow-spec） |
| 2–3 方案与取舍 | **任意 G{n}** 内多方案子流程（本节） |
| 分段确认 | 各 **G{n} 收口** + **Qclose-1** |
