# brainstorming 与 sdx-prd 的衔接（嵌入层）

本文件说明：在 **`/sdx-prd` 阶段二**如何把 **brainstorming** 的对话节奏嵌入门禁 **G{n}**，并与 Q-n、C/M/S/F 协同。执行阶段二时**建议打开本文**，避免与独立执行 `/brainstorming` 时的默认产物与终态混淆。

---

## 与独立 `/brainstorming` 的差异（须牢记）

| 维度 | 独立 `/brainstorming` | 本技能内嵌（阶段二） |
|------|----------------------|----------------------|
| 主产物 | 常为 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` | 会话 spec：`...-sdx-prd.md`；终稿：`PRD-*.md`（`requirements/` 下） |
| 正常终态 | 经批准后进入 `writing-plans` 等实现计划 | **Qclose-1** → 阶段三分块定稿；**不**在本会话内以 `writing-plans` 作为默认收尾 |
| HARD-GATE | 以 brainstorming 技能为准 | **仍以 sdx-prd HARD-GATE 为准**：总确认前默认不写 `{DOC_DIR}/requirements/**/PRD-*.md` |

**禁止**：在仅执行 `/sdx-prd` 的对话中，用「已完成 brainstorming」为由跳过 Gn 收口、门禁标记或 Qclose-1；也**禁止**默认创建 `*-design.md` 替代本会话 spec。

若用户**明确需要**一份独立设计 spec，应**另开会话**执行 `/brainstorming`，再在后续会话用本技能消费其结论。

---

## 嵌入层：何时触发

在阶段二**任意门禁 G{n}** 内，出现以下任一情况，即进入 **brainstorming 式子流程**（可与 Q-n 交替，但须保持「一次只推进一条主线」）：

1. **多套可取舍方案**：同一门禁下存在两条及以上**真实可选**的路径（流程主路径、用例粒度、故事拆分、模块边界、验收切法等），需要用户做取舍。
2. **需要结构化权衡**：不仅缺信息（那是 **Q-n**），而是信息足够但**利弊并存**，需对比后再写入「本门禁结论」。

**不必触发**：仅有一个合理路径、或仅需澄清事实而无方案分叉时，按原有草案 → 确认点 → 收口即可。

---

## G{n} 内「多方案」子流程（推荐顺序）

在**该 G{n} 未收口前**完成：

1. **点名方案**：列出 **2–3 套**（或「维持现状 / 变更 A / 变更 B」）。名称须为**业务语义**（与 [workflow-spec.md](workflow-spec.md) 中 Q-n 要求一致），避免空洞的「方案A/方案B」字样。
2. **利弊与取舍**：每套给出适用条件、成本/风险要点、不适用场景；给出**推荐项及理由**（可被拒绝）。
3. **用户确认**：用本技能**标准四选项**（C/M/S/F）收口本门禁；结论写入 spec 的「本门禁结论」，并注明被选方案及未选方案的搁置理由（若适用）。

与 **Q-n** 的分工：

- **Q-n**：信息不足、歧义、矛盾待澄清 → 每次一题，见 workflow-spec。
- **多方案子流程**：信息已够，但**决策分叉** → 用本节结构；若分叉内仍有事实缺口，先收敛 Q-n，再回到方案对比。

## 与各门禁的典型触发（非穷尽）

| 门禁 | 可能出现的「多套方案」示例 |
|------|---------------------------|
| G1（§1） | 成功标准优先级、MVP 叙事侧重点不同 |
| G2（§2） | 主流程分叉、异常处理策略不同 |
| G3（§3） | 交互深度 vs 轻量引导 |
| G4（§4） | 用例粒度、是否合并子用例 |
| G5（§5） | 故事拆分粒度、验收颗粒度 |
| G6–G8 | 模块划分、规则口径、数据字典详略 |
| G9–G10 | NFR 强度、验收可测表述 |
| G11（§11） | 附录详略、对外承诺级别 |

**精简 6G** 下，合并门禁内更易出现多方案对比，仍须在**当前合并门**内完成取舍再收口。

## 与 brainstorming 检查清单的对照（阶段二内）

| brainstorming 要点 | 在 sdx-prd 中的落点 |
|---------------------|---------------------|
| 探索项目上下文 | G1 前及回跳后材料不足时补充 |
| 单题澄清 | **Q-n**（workflow-spec） |
| 2–3 方案与取舍 | **任意 G{n}** 内多方案子流程（本节） |
| 分段确认 | 各 **G{n} 收口** + **Qclose-1** |
