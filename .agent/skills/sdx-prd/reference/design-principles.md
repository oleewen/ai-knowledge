# 设计原则与反模式（sdx-prd）

SKILL.md「核心约束」为精简版，本文件为完整规范。质量验收清单见 [quality-checklist.md](quality-checklist.md)（本文件讲原则，清单可执行）。

---

## 设计原则

### 1. 模板驱动

严格遵循 [../assets/prd-template.md](../assets/prd-template.md) 十一章结构（§1–§11）。章节顺序与顶层编号不可调整；无内容的章节保留标题并标注「不适用」或「待补充」。

### 2. 证据优先

用户故事、业务流程与业务规则须引用需求分析文档（FR-n、BR-n）与 `knowledge/` 事实，禁止凭空臆测。

| 证据类型 | 格式 | 示例 |
|----------|------|------|
| 功能需求 | `FR-{NNN}` | `FR-001 创建申诉单` |
| 业务规则 | `BR-{NNN}` | `BR-001 申诉时效校验` |
| 用户故事 | `US-{NNN}` | `US-001` |
| 用例 | `UC-{NNN}` | `UC-001` |
| 异常场景 | `EX-{NNN}` | `EX-001` |
| 功能验收标准 | `AC-{NNN}` | `AC-001` |
| 非功能验收标准 | `NAC-{NNN}` | `NAC-001` |

### 3. 按需加载

仅在本轮任务需要时打开文件；禁止为「完整性」通读 `knowledge/**` 或全仓源码。

### 4. 歧义标注

对歧义、矛盾、信息缺失，标注为待澄清项，暂停并请求用户澄清。禁止自行假设缺失信息后继续。

### 5. MVP 聚焦

PRD 仅覆盖目标 MVP 阶段（`--mvp`）范围内的功能需求。不得将后续 MVP 的需求混入当前 PRD。

### 6. 可追溯性（SDD 链式表述）

`SOLUTION → ANALYSIS（FR/BR/NFR）→ PRD（流程/用例/故事/验收）`

- US-n → FR-n（功能需求）
- UC-n ↔ US-n（双向映射）
- BR-n → ANALYSIS BR-n（继承）
- AC-n / NAC-n → US-n 或 §9 NFR
- EX-n → 业务流程步骤

### 7. FR 句式（能力契约）

FR-n 在 PRD 中展开时，保持**能力陈述、实现无关、可验收**：

- **推荐**：「{角色} 可以 {业务能力}，使得 {可观察结果}」
- **避免**：具体技术栈、库名、表字段、中间件名作为「需求」写入 PRD 正文

### 8. NFR 与验收对齐

- §9 为 NFR 陈述，每类给出指标/阈值 + 度量方法
- §10.2 NAC 与 §9 互链；条目应可对应或显式标注「不适用」

## 反模式清单（禁止）

| 反模式 | 说明 |
|--------|------|
| 臆测需求 | 未引用 FR-n 即自行补充用户故事或业务流程 |
| 吞没歧义 | 将不明确需求自行补全后继续，不标注待澄清 |
| 实现泄漏 | 在 PRD 中写入接口定义、数据库表设计、中间件选型等技术细节 |
| 模板跳章 | 跳过或重排 prd-template.md 的章节结构 |
| 通读全库 | 一次性读取全仓知识库而不考虑本轮任务实际需要 |
| 无编号引用 | 用户故事/用例/业务规则/验收标准无统一编号，导致不可追溯 |
| MVP 越界 | 将非当前 MVP 范围的功能需求纳入 PRD |
| 故事堆砌 | 用户故事仅复制 FR-n 描述而未展开为具体场景与验收标准 |
| 空章提交 | 章节标题下无任何内容且未标注「不适用」或「待补充」 |
| 规则散落 | 业务规则散布在流程/故事/用例中未在 §7 汇总 |

## 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| 需求分析文档不存在 | 终止，提示先执行 sdx-analysis |
| 需求分析文档中无对应 MVP 章节 | 终止，提示检查 MVP 编号或先完成 MVP 拆分 |
| 需求分析文档结构不完整 | 发出警告，列出缺失章节，基于已有内容继续并标注风险 |
| knowledge 目录缺失 | 发出警告，仅基于需求分析文档完成 PRD，标注缺少知识库基线 |
| 模板文件不存在 | 终止，提示确认 `.agent/skills/sdx-prd/assets/prd-template.md` 存在 |
| FR-n 与 US-n 映射不完整 | 暂停，输出未覆盖的 FR-n 清单，请求用户确认是否遗漏 |
| 输出目录不存在 | 自动创建 `{DOC_DIR}/requirements/REQUIREMENT-{IDEA-ID}/MVP-Phase-{N}/` 目录 |
