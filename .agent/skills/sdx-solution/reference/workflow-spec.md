# 工作流详细规范（sdx-solution）

[SKILL.md](../SKILL.md) 中的流程为摘要，本文件为完整规范，覆盖闸门状态机、回跳影响面、Q-n 协议与 chunk 边界。

---

## 闸门状态机

```
[阶段 1 参数解析]
    ↓ 全部 Q1 确认（或 S/F 跳过）
[阶段 2 逐闸交互]
    G1 → G2 → G3 → G4 → G5 → G6 → G7
    每闸：草案呈现 → 待确认点逐一确认 → 闸门收口
    ↓ 全部闸收口（或 S/F 跳过）
[Qclose-1 总确认]
    ↓ C / S（PENDING → CONFIRMED）
[阶段 3 文档生成]
    骨架 → chunk 1 → chunk 2 → chunk 3 → chunk 4 → chunk 5 → 终检
```

**精简 5 闸映射**：

| 精简闸门 | 覆盖 7 闸 | 覆盖模板 |
|---------|----------|---------|
| G(1–2) | G1、G2 | §1、§2 |
| G3 | G3 | §3 |
| G4 | G4 | §4 |
| G(5–6) | G5、G6 | §5、§6 |
| G7 | G7 | §7 |

## 回跳影响面评估

用户回跳到 G{k} 并修改结论后，评估后续闸的依赖类型：

| 依赖类型 | 判断标准 | 处理方式 |
|---------|---------|---------|
| 强依赖 | 后续闸与 G{k} 新结论显式矛盾，或引用同一实体 | 须重新确认 |
| 弱依赖 | 后续闸大量引用 G{k} 的术语/范围/C-n | 建议重新确认 |
| 无依赖 | 后续闸内容与 G{k} 无关联 | 保持已确认状态 |

向用户说明影响面后，由用户选择「仅强依赖重走」或「强弱一并重走」。

## 待澄清项（Q-n）交互确认协议

**触发时机**：阶段 2 任意闸门中出现歧义、矛盾或信息缺失时，立即标注 Q-n。

**交互格式**：

```
Q-{n}：{问题描述}

背景：{为什么需要澄清，影响哪个决策}

选项：
1. {具体业务含义描述}（推荐）
2. {具体业务含义描述}
3. {具体业务含义描述}
4. 其他（请说明）

请选择：
C：确认选项 1（推荐）
M：修改，格式 "M 旧内容 - 新内容"
S：跳过，标注为待澄清
F：跳过后续全部闸门，直接写草稿
```

**规则**：
- 每次只提一个 Q-n，等用户回答后再提下一题
- 选项描述具体业务含义，不写「方案A/方案B」等抽象标签
- 澄清结论写入对应闸门的 spec 章节，不单独设「待澄清问题」章
- 用户选 S 时，在 spec 中标注「Q-{n} 待澄清」并说明影响范围

**可选：Q-n 优先模式**

当同一份 spec 中登记了多条 Q-n 且用户希望先收敛歧义时，可在全部闸草案完成后，先逐一确认所有 Q-n，再进行分闸摘要确认，最后进入 Qclose-1。

## 阶段 3 chunk 边界

| Chunk | 覆盖章节 | 完成标志 |
|-------|---------|---------|
| 1 | §1 背景与目标、§2 范围与约束 | 业务目标 G-n 可追溯，范围 In/Out 明确 |
| 2 | §3 影响与冲突 | §3.4 C-n 表完整，每项有化解方案与成本 |
| 3 | §4 思路与方案 | 解决思路可读，关键决策有推荐与理由 |
| 4 | §5 风险与待定、§6 交付计划 | R-n 有应对策略，MVP 依赖无环 |
| 5 | §7 附录（含 §7.4 勾选） | 质量自查表已逐项判定 |

用户选 F（跳过后续 chunk 轻确认）时，助手一次性填充至可终检前状态，并说明填充策略。

---

## 阶段 2 禁止套话

进入阶段 2 后，禁止以下句式起首（含变体）：
- 「已在 `…/specs/….md` 中补充 G{n} 草案，要点如下：」
- 「已写入/已更新该文件」
- 「已补充 G{n} 草案」

应直接给出要点、待确认点或标准四选项提示；会话 spec 路径非必要不重复。
