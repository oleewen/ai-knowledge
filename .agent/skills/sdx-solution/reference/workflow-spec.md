# 工作流规范（sdx-solution）

SKILL.md 中的流程为主干，本文件补充门禁状态机、回跳影响面评估与 Q-n 协议细节。

---

## 门禁状态机

```
[阶段一：参数确认]
    ↓ 全部参数确认（或 S/F 跳过）
[阶段二：逐门禁交互]
    G1 → G2 → G3 → G4 → G5 → G6 → G7
    每门禁：草案呈现 → （可选）多方案对比 → 待确认点逐一确认 → 门禁收口
    多方案对比：见「G{n} 内多方案子循环」与 [brainstorming-integration.md](brainstorming-integration.md)
    ↓ 全部门禁收口（或 S/F 跳过）
[Qclose-1 总确认]
    ↓ C / S（PENDING → CONFIRMED）
[阶段三：文档生成]
    骨架 → chunk 1 → chunk 2 → chunk 3 → chunk 4 → chunk 5 → 终检
```

**精简 5 门禁映射**：

| 精简门禁 | 覆盖 7 门禁 | 覆盖模板 |
|---------|----------|---------|
| G(1–2) | G1、G2 | §1、§2 |
| G3 | G3 | §3 |
| G4 | G4 | §4 |
| G(5–6) | G5、G6 | §5、§6 |
| G7 | G7 | §7 |

## 回跳影响面评估

用户回跳到 G{k} 并修改结论后，评估后续门禁的依赖类型：

| 依赖类型 | 判断标准 | 处理方式 |
|---------|---------|---------|
| 强依赖 | 后续门禁与 G{k} 新结论显式矛盾，或引用同一实体 | 须重新确认 |
| 弱依赖 | 后续门禁大量引用 G{k} 的术语/范围/C-n | 建议重新确认 |
| 无依赖 | 后续门禁内容与 G{k} 无关联 | 保持已确认状态 |

向用户说明影响面后，由用户选择「仅强依赖重走」或「强弱一并重走」。

## G{n} 内多方案子循环

**触发**：当前门禁的结论依赖**两条及以上真实可选路径**（范围、化解策略、思路、风险应对、MVP 切法等），需要先取舍再定稿。详见 [brainstorming-integration.md](brainstorming-integration.md)。

**节奏**（仍在同一 G{n} 内，未收口前）：

1. 列出 2–3 套路径，**业务语义命名**（避免空洞的「方案A/B」）。
2. 利弊、适用条件、推荐及理由。
3. 用标准四选项收口，结论写入 spec「本门禁结论」。

**与 Q-n 的分工**：Q-n 解决**信息缺口**；本节解决**信息足够但决策分叉**。若分叉内仍有事实未清，先 Q-n，再回到方案对比。

## 待澄清项（Q-n）交互协议

**触发时机**：阶段二任意门禁中出现歧义、矛盾或信息缺失时，立即标注 Q-n。

**交互格式**：

```
Q-{n}：{问题描述}

背景：{为什么需要澄清，影响哪个决策}

选项：
1. {具体业务含义描述}（推荐）
2. {具体业务含义描述}
3. {具体业务含义描述}
4. 其他（请说明）

请选择：
C：确认选项 1（推荐）
M：修改，格式 "M 旧内容 - 新内容"
S：跳过，标注为待澄清
F：跳过门禁，拟定草稿
```

**规则**：
- 每次只提一个 Q-n，等用户回答后再提下一题
- 选项描述具体业务含义，不写「方案A/方案B」等抽象标签
- 澄清结论写入对应门禁的 spec 章节，不单独设「待澄清问题」章
- 用户选 S 时，在 spec 中标注「Q-{n} 待澄清」并说明影响范围

**Q-n 优先模式**（可选）：当同一份 spec 中登记了多条 Q-n 且用户希望先收敛歧义时，可在全部门禁草案完成后，先逐一确认所有 Q-n，再进行分门禁摘要确认，最后进入 Qclose-1。

## 阶段三 chunk 完成标志

| Chunk | 覆盖章节 | 完成标志 |
|-------|---------|---------|
| 1 | §1、§2 | 业务目标 G-n 可追溯，范围 In/Out 明确 |
