# 设计原则与反模式（sdx-solution）

[SKILL.md](../SKILL.md) 中的「核心约束」为精简版，本文件为完整规范。验收勾选项见 [quality-checklist.md](quality-checklist.md)。

---

## 设计原则

### 1. 模板驱动

输出严格遵循 [../assets/solution-template.md](../assets/solution-template.md) 的**七章**结构。章节顺序与编号不可调整；无内容的章节保留标题并标注「不适用」或「待补充」，禁止整节空白。

### 2. 业务可读

正文（§1–§6 及 §7.1–§7.2）无接口名、表名/字段名、中间件、模块名、协议栈等工程标识。确需保留的技术线索**仅**在 §7.3 并含「待研发确认」。细则见 [audience-and-language.md](audience-and-language.md)。

### 3. 证据优先

影响面、冲突、风险须引用 `knowledge/` 事实或原始需求材料，禁止凭空臆测。引用格式：

| 证据类型 | 格式 | 示例 |
|---------|------|------|
| 业务目标 | `G-{N}` | `G-1 提升申诉处理效率` |
| 知识库实体 | `{视角}-{ID}` | `BC-001 FeeAppealContext` |
| 文档章节 | `{文件} §{章节}` | `INDEX_GUIDE.md §3.2` |

### 4. 歧义标注

歧义、矛盾、信息缺失须标注为 Q-n，逐一向用户提问确认，禁止自行假设后继续。Q-n 协议见 [workflow-spec.md](workflow-spec.md)。

### 5. 按需加载

仅在本轮任务需要时打开文件，禁止为「完整性」通读 `knowledge/**` 或全仓源码。

### 6. 可追溯性

- 业务目标 G-n 可指回需求来源/原始材料
- 影响项、C-n、R-n 可指回业务能力/协作环节
- 编号连续无断号（允许声明跳号原因）

## 反模式清单（禁止）

| 反模式 | 说明 |
|--------|------|
| 臆测影响面 | 未引用 knowledge 或原始材料即自行补充影响范围 |
| 吞没歧义 | 将不明确需求自行补全后继续，不标注 Q-n |
| 技术语言混入正文 | 接口名、表名、中间件等散落于 §1–§6 正文 |
| 模板跳章 | 跳过或重排 solution-template.md 的章节结构 |
| 空章提交 | 章节标题下无任何内容且未标注「不适用」或「待补充」 |
| 目标不可度量 | G-n 写「提升用户体验」等无法验证的空话 |
| MVP 无业务价值 | MVP 无法独立演示给业务方或解决具体业务问题 |
| 冲突表留空 | §3.4 无内容且未说明「经扫描无冲突」 |
| 文件头元数据 | 在文件开头使用 `---` YAML；正确做法为仅在文末「## 文档元数据」内填写 |
| 骨架当终稿 | 阶段 3.1 骨架未完成 chunk 填充即对外评审 |

## 错误处理

| 错误场景 | 处理方式 |
|---------|---------|
| 业务描述过于简短 | 暂停，请求用户补充背景与期望价值，不凭印象推测 |
| knowledge 目录缺失 | 发出警告，仅基于原始需求描述完成分析，在 §7.2 标注「缺少知识库基线」 |
| 模板文件不存在 | 终止，提示创建 `.agent/skills/sdx-solution/assets/solution-template.md` |
| MVP 拆分出现循环依赖 | 终止拆分，输出依赖图，请求用户确认调整方案 |
| 输出目录不存在 | 自动创建 `{DOC_DIR}/solutions/` 目录 |
