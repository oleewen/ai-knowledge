# brainstorming 嵌入层（sdx-test）

说明阶段二如何在门禁 G{n} 内嵌入 brainstorming 节奏，以及与独立 `/brainstorming` 的差异。

---

## 与独立 `/brainstorming` 的差异

| 维度 | 独立 `/brainstorming` | 本技能内嵌（阶段二） |
|------|----------------------|----------------------|
| 主产物 | 常为 `*-design.md` + `writing-plans` | 会话 spec：`...-sdx-test.md`；终稿：`TDD-*.md` |
| 正常终态 | 进入 `writing-plans` 等实现计划 | **Qclose-1** → 阶段三分块定稿 |
| HARD-GATE | 以 brainstorming 技能为准 | **仍以 sdx-test HARD-GATE 为准** |

**禁止**：在仅执行 `/sdx-test` 的对话中，用「已完成 brainstorming」为由跳过 Gn 收口、门禁标记或 Qclose-1；也**禁止**默认创建 `*-design.md` 替代本会话 spec。

若用户明确需要独立设计 spec，应**另开会话**执行 `/brainstorming`，再在后续会话用本技能消费其结论。

---

## G{n} 内多方案子流程

**触发**：当前门禁的结论依赖两条及以上真实可选路径（测试层次取舍、回归范围、数据准备策略、进出标准阈值等）。

**节奏**（仍在同一 G{n} 内，未收口前）：

1. 列出 **2–3 套**路径，**语义命名**（避免空洞的「方案A/B」）
2. 给出利弊、适用条件、推荐及理由
3. 用标准四选项收口，结论写入 spec「本门禁结论」，注明被选方案及未选方案的搁置理由

**与 Q-n 的分工**：Q-n 解决**信息缺口**；本节解决**信息足够但决策分叉**。若分叉内仍有事实缺口，先收敛 Q-n，再回到方案对比。

---

## 各门禁典型触发（非穷尽）

| 门禁 | 可能出现的「多套方案」示例 |
|------|--------------------------|
| G1 | 测试层次配比、覆盖率目标与项目现实的权衡 |
| G2 | 用例粒度、P0 边界、是否单独列出某类异常 |
| G3 | 数据脱敏 vs 合成数据、脚本化程度 |
| G4 | Mock 深度、环境对齐生产 vs 简化环境 |
| G5 | 退出标准严格度、缺陷容忍策略 |
| G6 | 附录粒度、对外承诺级别 |

**G2** 常为多方案密集区，但不限于此：只要当前 G{n} 的结论依赖方案选择，就应在本门禁内完成对比再收口。
