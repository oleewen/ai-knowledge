# 联邦原则与映射规范

docs-distill 的联邦层级约定、overview 蒸馏规则与质量自检标准。

---

## 蒸馏目标

蒸馏写入的唯一目标文件：

```
system/architecture/overview/{APPNAME}-overview.md
```

文件不存在时以 `system/architecture/overview/NAME-overview.md` 为模板创建（替换 NAME → APPNAME，同时替换文件内标题 `# {NAME} 架构概览` 中的 `{NAME}` → `APPNAME`）。

以下文件**仅作为知识来源**，不直接蒸馏：
- `system/architecture/business/`、`product/`、`application/`、`technical/`、`data/` 下各视角详细文档（提供「应填内容 + 产出建议」规范）
- 应用侧 knowledge YAML/MD（提供应用实际业务知识）
- 应用侧 SDD 文档（solutions/analysis/requirements，提供方案与需求知识）

---

## 联邦层级约定

| 层级 | 适合放什么 | 不适合 |
|------|-----------|--------|
| **应用知识库** | 业务规则细节、用户故事/用例、接口设计/类图/处理过程、部署参数、数据表结构 | 跨应用映射、系统级架构摘要 |
| **系统知识库** | 业务架构摘要（业务概述/域/流程/模型/术语/能力）、产品架构摘要（功能架构/用户旅程/信息架构/体验/运营/度量）、应用架构摘要（服务边界/领域模型/服务交互/接口管理/集成）、技术架构摘要（基础设施/中间件/高可用/性能/安全/可观测性）、数据架构摘要（数据模型/存储/流转/数仓/治理/安全/应用）、ID 契约 | 应用侧接口细节、OpenAPI 全文、数据表 DDL |

## overview 蒸馏规则

overview 蒸馏遵循**提炼原则**：从应用侧 knowledge 和 SDD 文档中提取有效信息，按五架构视角逐节写入 `{APPNAME}-overview.md` 第三列，禁止整段复制原始文档。

### 提炼步骤

1. 检查 `{APPNAME}-overview.md` 是否存在；不存在则以模板创建（替换 NAME → APPNAME）
2. 读取应用侧 knowledge（四视角 YAML/MD）和 SDD 文档，作为提炼的知识来源
3. 读取 `{APPNAME}-overview.md` 五架构视角知识索引表，逐条处理每一行：
   a. 读取副标题列链接对应章节的「应填内容」和「产出建议」注释，了解该节期望的内容格式
   b. 从应用侧知识来源中找到对应信息，按要求提炼
   c. 判断变动类型并写入第三列：
   - 原第三列为 `—` 或空：标注 `**[A]**`（新增）
   - 原第三列有内容且本次有变化：标注 `**[U]**`（变更）
   - 原第三列有内容但本次应删除：标注 `**[D]**`（删除，清空内容）
   - 原第三列有内容且本次无变化：保持原内容，不加标注

### 五架构视角蒸馏顺序

按以下顺序逐节处理，保证语义收敛：

1. **业务架构**（业务概述 → 业务域 → 业务流程 → 业务角色 → 业务规则 → 业务术语 → 业务能力 → 商业模式）
2. **产品架构**（产品概述 → 功能架构 → 用户旅程 → 信息架构 → 交互体验 → 多端策略 → 运营支撑 → 产品度量 → 版本发布）
3. **应用架构**（架构概述 → 应用全景 → 服务设计 → 领域模型 → 服务交互 → 接口管理 → 集成架构 → 多租户/多环境 → ADR）
4. **技术架构**（技术概述 → 基础设施 → 中间件 → 高可用 → 性能扩展 → 安全 → 可观测性 → DevOps → 开发环境）
5. **数据架构**（数据概述 → 数据模型 → 数据存储 → 数据流转 → 数仓/数据湖 → 数据治理 → 数据安全 → 数据分析）

### 撰写规则

- **先读再写**：先读副标题链接对应章节的「应填内容 + 产出建议」，再提炼写入
- **完整内容**：第三列可写多段、列表、小表格，是该应用的完整知识快照
- **不整段复制**：提炼有效信息，改写为适合系统库的表达，不粘贴原始文档段落
- **无内容时留空**：应用侧无对应信息时，第三列写 `—`，不强行填充

---

## 质量自检

- 五架构视角全部章节行均已处理（有内容或明确标 `—`）
- 第三列内容符合对应章节「应填内容」要求，非整段复制
- 变动标识（A/U/D）准确反映本次蒸馏的实际变化
- 应用侧细节（接口 DDL、用户故事原文等）未出现在第三列
- 文件名为 `{APPNAME}-overview.md`，标题为 `# {APPNAME} 架构概览`
