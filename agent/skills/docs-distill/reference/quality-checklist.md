# 蒸馏落盘质量清单

在执行工作流步骤 5（文档检查与冲突处理）时逐项对照。

## 结构

- [ ] 标题层级与同目录姊妹文件一致  
- [ ] 表格列、列表符号与既有惯例一致  
- [ ] 站内链接为合法相对路径（见 [gates-and-links.md](gates-and-links.md)）  

## 语义与冲突（三类一致性）

| 类型 | 说明 |
|------|------|
| **内部** | 同一文档内前后术语、数字、流程是否矛盾 |
| **目标侧** | 与目标目录下其他已存在文档是否矛盾 |
| **来源对齐** | 蒸馏结论是否在来源中有依据；来源本身矛盾时不得静默合并 |

发现任一类问题：**停止继续扩展范围**，列出「冲突点清单」（每条：位置、原文摘录、冲突描述、可选处理 A/B）。

## 冲突解决节奏

- 一次只问一个决策点（或一组强绑定的二选一）。  
- 用户选定后再改文档并针对该条复查。  
- 若用户要求保留两种说法，须在正文中显式标注不确定性或「待业务确认」（用语与用户约定一致）。

## 收口检查（步骤 5～6）

- [ ] 方案确认书已获用户肯定后再落盘  
- [ ] 目标结构与同级文档一致  
- [ ] 无未解决的内部/跨文档/来源矛盾，或已标注并获用户认可  
- [ ] 索引或导航文件若需同步已一并更新  
- [ ] 未擅自扩大用户确认的范围  
- [ ] 会话末提供变更摘要；未自动执行 `git commit` / `git push`
