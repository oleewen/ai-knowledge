# 蒸馏前职责与粒度闭合

本步骤核对预览或写入所需的职责契约。目标是让「源槽位能上行什么、目标层应保留多粗」都有落盘依据。

## 信任边界

只信以下契约：

- 跨层：`agent/knowledge/knowledge-governance.md` 的层职责与聚焦摘要
- 目标：同层 `knowledge/overview/NAME-overview.md` 表行和 `agent/references/knowledge-layout.md`
- 源：槽位根 `README.md` 与槽位 `knowledge/` 入口

不得从 overview 已有正文或槽位正文归纳职责；会话中的口头结论必须先写回约定契约路径。

## 必须闭合

1. **表行级**：目标层哪些行属于本单元；一行一条要点，不能塞入下层长文。
2. **摘要级**：每条要点是可独立检索的概念或能力；不写过程流水和实现细节堆砌。
3. **跨层收束**：源侧更细、目标侧更粗时，契约写明如何收束；没有规则就硬停。

## 对照顺序

1. 读目标层契约和表行，摘录目标职责与粒度。
2. 读槽位 README 与 knowledge 入口，摘录源职责。
3. 任一缺失、模糊或冲突：停下，给数字选项和落盘目标；不偏向目标或源。
4. 决策落盘后输出摘要；只读预览直接继续，正式写入核对有效授权。

## 必出摘要

```markdown
### 职责与粒度摘要（契约级）
- 目标层职责：…（锚点：路径 §节）
- 源侧职责：…（锚点：路径 §节）
- 本层要点粒度：…
- 跨层收束：…
- 已知缺口/冲突：无 | …
```

## 硬停面

缺口或冲突时，输出：缺失路径或短引、推荐选项、落盘目标、明确「未落盘且未再确认前不预览、不写入」。

## 自检

- [ ] 必读契约齐全；没有从正文猜职责。
- [ ] 三项粒度均有契约依据。
- [ ] 冲突已决策并落盘。
- [ ] 摘要已出示；正式写入已获有效授权，只读预览不要求额外确认。
- [ ] 未闭合时未 dry-run、未写第三列。
