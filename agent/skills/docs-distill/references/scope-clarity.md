# 蒸馏前职责与粒度闭合

主干：[SKILL.md](../SKILL.md)。推进 binding：[gates.md](gates.md)。流程：[workflow.md](workflow.md)。

> **定位**：写前意图澄清（`C`）内的 **契约级** 职责范围 / 知识要点粒度 / 跨层收束检查。  
> **不是** 写后 grilling；禁止把本步称作「写前 grilling」。

## 目的

蒸馏写第三列之前，先对齐：

1. **目标层** knowledge 职责边界（本层管什么、不管什么）
2. **源槽位** 对应知识库职责边界
3. **要点粒度**（表行级 + 摘要口径 + 源细→目标粗的收束规则）

契约缺失、表述模糊、双边冲突 → **硬停**，列决策项；结论 **先落盘契约** 再算 `C` 闭合。未闭合前：不 `--dry-run`、不写 overview。

## 信任边界

- **只信已落盘契约**（见下方清单）。
- **禁止**从 overview 已写行或槽位 knowledge 正文 **归纳**「大概职责/粒度」当闭合依据。
- 人在会话中的答复：须写回约定契约路径后，才可继续本单元。

## 必读清单

| 侧 | 必读 |
| --- | --- |
| 跨层 | [knowledge-governance.md](../../../knowledge/knowledge-governance.md)「三层职责边界」 |
| 目标层 | `{DOC_DIR}/DESIGN.md`；同层 `knowledge/overview/NAME-overview.md` 表行真源；[knowledge-layout.md](../../../references/knowledge-layout.md) 中 overview / 表行相关节 |
| 源侧 | 槽位根下 `DESIGN.md`（`system` 边 → `application-slots/application-{NAME}/DESIGN.md`；`company` 边 → `system-slots/system-{NAME}/DESIGN.md`） |

任一项缺失 → 硬停，列缺失路径。README 叙事不作本闭合的硬依赖。

## 粒度须核（三条皆要有契约依据）

1. **表行级**：哪些 overview 行属于本层；一行一条要点；禁止把下层长文整段塞进第三列。
2. **摘要口径**：一条要点对应一个可独立检索的概念/能力；禁止过程流水、禁止实现细节堆砌（须在契约中有写明或可直接引用的表述）。
3. **跨层收束**：源侧细、目标层粗时，契约须写明上行如何收束；否则当模糊点硬停。

## 双边对照顺序

1. 读目标侧清单 → 归纳本层职责与粒度（仅摘契约原文要点，不发明）
2. 读源侧 `DESIGN.md` → 对照
3. **冲突或一边有、一边无** → 一律硬停提问；**不**自动偏目标或源
4. 人选定后 → **先落盘**（改目标/源 DESIGN 或 governance 相关节，路径在决策面写明）→ 再输出完整澄清摘要 → 写前 `C`

## 写前摘要（必出）

契约齐全也须输出；人确认后才算本技能写前 `C` 可过。建议结构：

```markdown
### 职责与粒度摘要（契约级）
- 目标层职责：…（锚点：路径 §节）
- 源侧职责：…（锚点：…）
- 本层要点粒度：表行 / 摘要口径 …
- 跨层收束：…（或「契约已写明：…」）
- 已知缺口/冲突：无 | …
```

同时仍须满足 [intent-clarify.md](../../../references/intent-clarify.md) 公共六项 + [gates.md](gates.md) 追加字段。

## 硬停决策面

输出须含：

- 缺失路径或冲突摘录（短引契约原文）
- 推荐选项（数字编号）与推荐项
- 落盘目标路径（改哪份 DESIGN / 哪一节）
- 明确：未落盘且未再确认前，不预览、不写入

一次一问填缺口（与 intent-clarify「有缺口」一致）；全部闭合后再出一屏总确认。

## 与烤干的边界

| | 写前本步 | 写后烤干 |
| --- | --- | --- |
| 时机 | 意图澄清内 | 写入或 dry-run 预览后 |
| 材料 | 仅必读契约清单 | 第三列成品 / 预览 |
| 深度 | 职责、粒度、收束是否闭合 | 语义质量、可评审性、遗漏 |
