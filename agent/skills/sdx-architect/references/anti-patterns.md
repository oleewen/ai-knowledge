# sdx-architect 常见反模式

## 反模式与纠正动作

1. **未确认先落盘**
   - 表现：用户总确认前直接写入 `ASD-*.md`。
   - 纠正：回到会话草稿，完成总确认后再落盘；或记录合法例外依据。

2. **ASD 混入 DSD 细节**
   - 表现：在 ASD 直接写实现级 API/DDL/完整规约正文。
   - 纠正：ASD 仅保留架构边界与规约摘要，细节下沉至 `/sdx-design`。

3. **章节缺失或失衡**
   - 表现：只写架构图，缺 `§1` 或 `§3`。
   - 纠正：按模板补齐 `§1/§2/§3`，先补骨架再补内容。

4. **追溯链断裂**
   - 表现：ASD 结论无法映射到 `PRD/ANALYSIS`。
   - 纠正：逐项补齐来源引用，删除无依据结论。

5. **命名路径不兼容**
   - 表现：文件名、目录层级、占位符替换不符合规范。
   - 纠正：统一为 `ASD-{IDEA-ID}-{N}.md` 与标准目录，修正占位符。

6. **门禁状态不透明**
   - 表现：未记录 `PENDING/CONFIRMED`，导致协作误判。
   - 纠正：在会话草稿明确门禁状态与确认结果。

7. **只产出图，不给决策**
   - 表现：有图无关键设计决策与理由。
   - 纠正：补充决策表，写清取舍与备选方案。

8. **校验缺失即宣告完成**
   - 表现：未执行 `validate-asd.sh` 即结束。
   - 纠正：把 validate 作为收尾必经步骤，失败即修复后重跑。
