# sdx-architect 行为评测

维护技能、修复已观察失败时使用 [evals.json](../evals/evals.json)；普通 ASD 编写不要求运行整套评测。JSON 可解析或结构校验通过，不等于行为评测通过。

## 执行

1. 每个用例使用隔离临时工作区。按 `setup` 准备最小原始文件和既有会话，保留执行前副本；材料只含场景事实，不填入期望答案。
2. 将技能、`prompt` 与原始材料交给独立执行者；不提供 `expected_output`、断言或本轮修复结论。目录中的路径按用例实际创建。
3. 允许执行者在临时区读取和修改用例目标。保存完整会话、工具调用、文件 diff 和实际校验输出。按 `continuation` 提供已规定的模拟回复；未规定的语义选择留待用户，不能替其决策。
4. 由 [grader](../agents/grader.md) 按断言与证据评分。没有执行、记录不足或尚未到达的阶段记 `not_run`，不要补写“通过”。
5. 有失败时交给 [analyzer](../agents/analyzer.md)；只修有证据支持的问题，再重跑相关场景。

路由用例只评首轮路由，不执行其他技能。写入用例须看产物与 diff，不能以流程宣言替代；当前段未推进到收尾时，不把尚未运行的整篇校验判为已执行。未闭合的场景可以部分评分，但不能宣称用例或整套通过。

## 结果记录

复制 [结果模板](../evals/eval-metadata-template.json)，填写运行标识、临时工作区和证据文件。每个 `results[]` 只引用 `eval_id`，包含：

- `status`：`pass | fail | not_run`。
- `text`：结论及未评估原因。
- `assertions[]`：每项为 `id`、`status`、`evidence`；证据列实际观察及文件/会话/工具位置。

断言 ID 以对应版本的用例为准，不在结果模板重复定义。模板空数组表示尚未运行；任何汇总都应同时报告通过、失败、未评估数量。
