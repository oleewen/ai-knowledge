# sdx-architect 质量检查清单

## 1) 结构完整性（必检）

- [ ] 文档包含 `§1 设计概述`、`§2 架构设计`、`§3 需求规约`。
- [ ] `§1` 包含目标、约束、关键决策等最小信息。
- [ ] `§2` 至少覆盖架构边界、服务变更或交互关系。
- [ ] `§3` 为规约摘要表，能明确服务能力与下游规约入口。
- [ ] 文末存在合法元数据块（YAML）。

## 2) 追溯一致性（必检）

- [ ] `ASD` 能回溯到同阶段输入：`PRD` 与 `ANALYSIS`。
- [ ] 不越界写入 `DSD` 细节：不在 ASD 中展开实现级 API/DDL/完整规约正文。
- [ ] 关键能力、术语、范围与 `PRD/ANALYSIS` 语义一致，无冲突表述。

## 3) 命名与路径兼容性（必检）

- [ ] 文件命名符合：`ASD-{IDEA-ID}-{N}.md`。
- [ ] 路径符合：`{DOC_DIR}/requirements/REQUIREMENT-{IDEA-ID}/MVP-Phase-{N}/`。
- [ ] `§3` 中规约文件路径与命名可被下游 `sdx-design` 复用。
- [ ] 占位变量（如 `{IDEA-ID}`、`{N}`、`{app-name}`）已替换且风格一致。

## 4) 门禁与校验（必检）

- [ ] 落盘前已完成“用户总确认”或满足合法例外。
- [ ] 已执行 `validate-asd.sh`，并处理校验失败项。
