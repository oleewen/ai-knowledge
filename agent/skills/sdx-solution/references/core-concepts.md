# sdx-solution 核心概念

## IDEA-ID

格式：`{YYMMDD}-{主题}`

- `YYMMDD`：日期，如 `260412`
- `主题`：中文短名，2–6 字；若含 ASCII slug，正文同一处备注中文题名

| 产物 | 路径示例 |
| --- | --- |
| 解决方案 | `{DOC_DIR}/solutions/SOLUTION-260412-审批提效.md` |
| 下游分析 | `{DOC_DIR}/analysis/ANALYSIS-260412-审批提效.md` |

## 编号

| 前缀 | 含义 | 例 |
| --- | --- | --- |
| G-n | §1.3 业务目标 | `G-1 …` |
| C-n | §3.4 冲突 | `C-1 …` |
| R-n | §5 风险 | `R-1 …` |
| Q-n | §5.2 问题决策（业务取舍；待确认或已决策） | `Q-1 …` |
| ADR-n | `{DOC_DIR}/adr/` 技术/架构决策（登记 CONTEXT） | `ADR-001 …` |

`G-n`、`C-n`、`R-n`、`Q-n` 均是终稿内的业务编号；技术决策编号见 ADR，不入 Q-n。本技能不再使用 `G{n}` 作为默认门禁编号主线。
§6.1 关键里程碑是下游 ANALYSIS 的**阶段骨架**：ANALYSIS 按表序 1:1 映射为 `MVP-n（{里程碑名}）`，**不另起阶段**；阶段内 FR 拆解归 ANALYSIS。SOLUTION 正文不强制写 `MVP-n`。

## `--depth`

| 值 | 含义 |
| --- | --- |
| `quick` | 压缩 §3；高影响项不可缺 |
| `standard` | 默认完整七章粒度 |
| `deep` | 加强数据影响与约束；正文仍须业务表述 |

## SOLUTION 七章

对齐 [solution-template.md](../assets/solution-template.md)：

| 章 | 内容 |
| --- | --- |
| §1 | 背景、问题、目标表（G-n：目标/度量/预期收益） |
| §2 | 场景、角色、In/Out、成功标准 |
| §3 | 影响面、冲突（C-n）与化解 |
| §4 | 思路、关键约束表 |
| §5 | 风险（R-n）、问题决策（Q-n 业务取舍；技术选型见 CONTEXT/ADR） |
| §6 | 关键里程碑、切换方案（弱绑定） |
| §7 | 术语、参考、内部参考（§7.3）、质量自查（§7.4） |

元数据：**要求**文首 `---` frontmatter；字段以模板为准。
