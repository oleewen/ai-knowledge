# sdx-solution 核心概念

## IDEA-ID

格式：`{YYMMDD}-{主题}`，语法见 [命名约定](../../../knowledge/naming-conventions.md)。这是该解决方案库一次分析主题/版本的标识，不与系统/应用的 `ANALYSIS`、`FEATURE` 共用。

| 产物 | 路径 |
| --- | --- |
| 解决方案分析 | `{DOC_DIR}/solutions/SOLUTION-{IDEA-ID}.md` |
| 依据 | 原始业务材料、同库 knowledge、已核实系统与公司技术基准；状态分别标明 |

## 多份与现行

- 每份记录当时依据下的完整分析；后继也独立可读，§1.3 说明相对前驱的变化。未变化的有效结论经核对后承接，不能只写增量让读者拼接。
- `parent` 填已有的 `SOLUTION-{IDEA-ID}`，不用路径或 `.md` 后缀；首份为空。同一前驱最多一个后继，链不得自指或成环。
- 未被其他文件用作 `parent` 的文件是现行候选。若有多份候选，由用户选择本次前驱，不按日期猜测。
- 新建后继不改前驱；用户明确指定的当前草稿可以续写、`M` 修改或按协议重开。不能因草稿已落盘就另建一份。

## 下游关系

SOLUTION 为系统分析提供目标、产品职责边界、系统承接、依赖与验收约束。系统分析按需引用，有上游方案时核对其约束；独立系统需求可直接启动。下游不用相同 IDEA-ID，也不把 SOLUTION 当作系统 PRD 的 parent。
