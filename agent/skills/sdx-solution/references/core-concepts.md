# 核心概念（sdx-solution）

---

## IDEA-ID

统一格式：`{YYMMDD}-{主题}`

- `YYMMDD`：创建日期，如 `260412`
- `主题`：以中文为主的短名，2–6 字，如 `审批提效`、`费用申诉优化`
- 若含 ASCII slug，须在 spec 本行备注中文题名

**路径示例**：

| 产物 | 路径 |
|------|------|
| 会话 spec | `docs/superpowers/specs/2026-04-12-审批提效-sdx-solution.md` |
| 解决方案 | `{DOC_DIR}/solutions/SOLUTION-260412-审批提效.md` |
| 下游分析 | `{DOC_DIR}/analysis/ANALYSIS-260412-审批提效.md` |

---

## 编号体系

| 前缀 | 用途 | 示例 |
|------|------|------|
| `G-n` | 业务目标条目（§1.3） | `G-1 提升审批效率` |
| `C-n` | 业务冲突（§3.4） | `C-1 规则冲突` |
| `R-n` | 风险（§5.1） | `R-1 进度风险` |
| `Q-n` | 待澄清问题（阶段二） | `Q-1 审批层级待确认` |
| `MVP-n` | 交付阶段（§6.1） | `MVP-1` |

> **G{n}**（大括号）= 流程门禁编号；**G-n**（连字符）= 业务目标编号，二者不可混用。

---

## 深度参数（--depth）

| 值 | 行为 |
|----|------|
| `quick` | 压缩 G3 叙述，至少列出高影响项 |
| `standard` | 扫描知识库，生成完整七章，标准叙述粒度（默认） |
| `deep` | 深度阅读知识库，含数据影响、历史约束分析；写入时仍须业务表述 |

## 解决方案文档（SOLUTION）七章结构

遵循 [../assets/solution-template.md](../assets/solution-template.md)：

| 章节 | 内容 |
|------|------|
| §1 背景与目标 | 业务现状、问题、目标（G-n）、价值 |
| §2 范围与约束 | 核心场景、角色、In/Out、约束 |
| §3 影响与冲突 | 影响面、冲突（C-n）及化解 |
| §4 思路与方案 | 解决思路、方案对比、关键决策 |
| §5 风险与待定 | 风险（R-n）、待澄清问题（Q-n） |
| §6 交付计划 | MVP 拆分、关键里程碑 |
| §7 附录 | 术语、参考、内部参考、质量自查（§7.4） |

**元数据**：仅在文末「## 文档元数据」内的 fenced `yaml` 中，禁止文件开头写 `---` YAML frontmatter。
