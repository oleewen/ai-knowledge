# sdx-solution 维护评测

仅维护技能时读取。脚本回归与行为评测分别记录；通过结构检查不能证明实体关系、授权或用户确认正确。

## 用例与隔离

[evals.json](../evals/evals.json) 是行为用例与断言真源，`base_files` 与每例 `files` 定义所需原始材料。按以下顺序执行：

1. 为每例新建临时容器，在 `repo/` 中物化 `base_files`，再应用本例 `files` 覆盖；值为 `null` 的键表示不物化该文件。所有键均相对 `repo/`，不得逃出容器。内容中的 `{{EVAL_ROOT}}` 只做字面替换，不用 shell 展开。创建 `agent-home/agents/configs`，内容为 `WORK_SPACE=<容器绝对路径>`。
2. 使用 Bash 5+ 从 `repo/` 加载源仓库 `agent/scripts/lib/docsconfig.sh` 并调用 `docsconfig_bootstrap_validate`，核实配置可加载。保存整个容器的初始快照。
3. 给独立执行者技能路径、临时工作区和本例 `prompt`；不给断言、预期结果或审查结论。允许读取技能及其引用，写入仅限容器。到实际需要用户补充或确认处即停，不代答。
4. 保存完整会话、工具轨迹、前后文件快照及 diff。产物用例须实际写文件；未写入用例也须用快照证明。校验输出记录命令与退出码。
5. 将原始材料和证据交 [grader](../agents/grader.md)；结果填 [记录模板](../evals/eval-metadata-template.json)。未运行或缺证据不记通过。

夹具中的知识文件只代表隔离测试事实，不是正式知识实体，也不要求复制完整业务知识库。路由和硬停例只检验当前请求，不执行下游技能。

## 验证与报告

同一 JSON 的 `discovery_cases` 独立验证自然语言发现：只给请求及可用技能目录，不预先指定或加载 sdx-solution。记录实际技能读取与文件操作；不得用显式 `$sdx-solution` 场景推定发现率。其状态与加载后的 `evals` 分开汇总，尚未运行保持 `not_run`。

从仓库根以 Bash 5+ 运行 `bash agent/skills/sdx-solution/tests/run.sh`，检查校验器的参数、身份、版本链、正文禁区及只读性。此命令不执行自然语言行为用例。

评测产物时，从临时 `repo/` 调用源仓库 `validate-solution.sh --file <产物路径>`；版本链检查仍覆盖整个 `solutions/`。空段可通过结构检查，须另外核实本轮授权段的实质内容。

报告分别列出静态检查、脚本回归、行为评测的已运行、通过、失败和未评估数。记录技能内容摘要、模型、日期和证据位置；历史结果不可冒充当前版本通过。修复只针对真实观察，再重跑相关例；普通业务写作不要求运行本套件。
