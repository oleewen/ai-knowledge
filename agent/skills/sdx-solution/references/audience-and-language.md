# sdx-solution 受众与语言

读者：**业务与产品**。写法：谁做了什么、流程与验收如何变，不写内部调用细节。

## 正文宜写 / 宜后置

| 宜写（业务） | 宜弱化（留给下游设计） |
|--------------|------------------------|
| 角色、场景、流程 | 类/接口/方法名 |
| 业务规则与边界（业务话术） | 表/字段、中间件名 |
| 成功标准、价值、MVP 边界 | 技术栈、部署形态 |
| 协作依赖（团队/环节） | 模块名、协议类型 |

## 转写示意

| 避免 | 推荐 |
|------|------|
| 调用 `FeeAppealService.create()` | 提交申诉后进入审核队列 |
| 写 `appeal_record` | 申诉记录可查可溯 |
| Kafka 异步通知下游 | 审批结果在约定时效内同步协作方 |
| P99 < 200ms | 高峰期体验须达标；与研发共定可测指标 |
