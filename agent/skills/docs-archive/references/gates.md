# 推进门禁

主干：[SKILL.md](../SKILL.md)。详细步骤：[workflow.md](workflow.md)。共享门禁见 [intent-clarify.md](../../../references/intent-clarify.md)、[unit-cycle-protocol.md](../../../references/unit-cycle-protocol.md) 和 [grilling-skill.md](../../../references/grilling-skill.md)。

当前单元 = 一个目标章节 + 对应 overview 行块。批次确认书收口后，单元只摘录目标与路径，不重复公共六项。

确认书必须承载公共六项，并追加来源、目标、映射、冲突策略、overview 回写策略和方案推荐。未获写前 C，不得写目标或回写 overview。

原始材料只读；overview 仅可回写确认书允许的行。归档正文写入范围限于确认书、目标章节和这些 overview 行；对应治理证据按 [知识证据登记](../../../knowledge/knowledge-evidence.md) 同批维护。交接另按现有 TODO 协议记录，不扩写实体或其他业务正文。

冲突必须已解决，或用户明确认可保留待确认状态及其影响；仅标注“待确认”不能通过验收，当前单元仍未收敛。

涉及实体结构化事实变化的当前单元，须先按 [实体交接](workflow.md#实体依赖与交接) 完成实体更新并重新核对。依赖未解除或 build 失败时，不写该单元章节、不清空其 overview delta；不能用“来源优先”或“待确认”章节替代实体更新。

写入顺序与失败保护（不是跨文件事务）：

1. 保留来源、目标文件、证据与 overview 的读取版本；每次写入前核对待写文件及所用来源仍为已核验版本。若已有其他编辑，停下重新核对差异，不能覆盖。
2. 先登记待落盘证据，再写目标章节，成功后补齐实际目标版本及核验结论。
3. 目标成功、证据一致并通过局部检查后，才回写 overview；回写前再次确认目标仍包含本轮已验收内容。
4. 任一步失败，停止当前单元的归档写入与推进，记录目标、证据及 overview 的实际状态。目标已成功但证据或 overview 失败时仍为未收敛，不得宣称全部完成。
5. 仅可恢复本轮 overview 差异；恢复前核对文件仍等于本轮写后版本。存在后续编辑或无法证明版本时，保留现场并报告冲突，不整文件覆盖旧快照，不修改原始材料。
6. 证据恢复遵同样的版本核对与本轮差异边界；无法恢复的部分状态保留并报告。Git 集成后重新核对来源、目标与证据映射；当前单元烤干收敛后，停等下一动作。

必须先停问：行内链接缺失或断链；来源/目标冲突无法消解；一次归档多个章节；清理 overview 第三列但未明确回写策略；目标体例与来源结构明显不一致。

证据元数据使用[共享生命周期工具](../../../knowledge/knowledge-evidence.md#工具生命周期)：先 `create` 登记待落盘，实际目标完成后 `update` 绑定字节哈希与人工结论，`check` 通过后才按当前单元规则推进。来源变化用 `refresh` 标记，版本变化新建并接续前序编号；部分元数据写入按原操作 ID `resume`。该工具不代写正文或 overview，也不以元数据操作完成替代当前单元验收。
