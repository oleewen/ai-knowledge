# docs-archive 常见陷阱

## 闸门与流程

- **未确认方案确认书就写入目标**：违反 `SKILL.md` HARD-GATE；即使用户说「快点改」，也须一句话概括方案与风险并取得**明确同意**。  
- **绕过 SDD/归档闸门**：目标在 `{DOC_DIR}` 受管路径或 `system/architecture/` 等时，须先对照 [CONVENTIONS.md](../../rules/CONVENTIONS.md)，不与 `sdx-*` 总确认抢跑。  
- **归档后立刻硬删来源**：未完成步骤 5 的一致性检查就删除 overview 容易误删或留下断链；至少完成本行落盘与自检后再回写清理，默认优先「仅保留索引壳」以保留可追溯入口。  

## 归档质量

- **过度摘要导致不可审计**：删除全部出处且目标读者需要追溯时，应保留「参见」或脚注路径。  
- **来源自相矛盾时静默选边**：必须停顿、列入冲突点清单，分步请用户裁决。  
- **结构照搬来源**：目标文档若有固定体例（如二级导语 + 三级小节），应**服从目标**而非复制来源标题层级。  

## 简写语法与路径

- **分隔符与路径冲突**：来源或目标路径中含 `-`、空格或与「`2`」「到」相邻时，可能误切分；应改用 `→` / `到` 或给路径加引号，并向用户确认两端边界。  

## 范围与一致性

- **擅自扩大映射表**：只写进方案确认书已映射的主题；新增主题须先更新确认书再获确认。  
- **只改正文不更新导航**：若目标目录依赖 README/INDEX 表，需在步骤 5 检查是否需同步（见 [quality-checklist.md](reference/quality-checklist.md)）。  

## 与相近技能混淆

- 需要提取实体 ID、刷新 `KNOWLEDGE_INDEX` → 用 `docs-build`，勿在本技能里造 ID。  
- 需要全库定向替换与引用链同步 → 用 `docs-upgrade`，勿与「业务叙述归档」混为一谈。
