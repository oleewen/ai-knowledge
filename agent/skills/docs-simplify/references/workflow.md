# docs-simplify 工作流

权限和停顿见 [gates.md](gates.md)；写作标准见 [精简原则](../../../references/simplify-principles.md)。

## 参数向导

从请求及前文提取目标、排除类、扩批策略、双目标顺序和起始单元。只问未决项；路径不明先搜候选。默认不含未点名的索引/日志/生成物。

## 当前单元

采用 gates 的文件、hunk 或已确认批次定义。读取原文与直接依赖；记录约束、例外、验收、契约字段和范围外内容，供写后对照。

## 写后默认表

| 对象 | 默认烤干 | 检查重点 |
| --- | --- | --- |
| 文件、hunk 或已确认批次 | 必须 | 内容无损、范围、契约、引用、受众；批次还查跨文件一致性 |

## 技能步骤

### 1. 锁定目标

按主诉求路由。纯术语纠错用 `docs-revise`，索引重建用 `docs-indexing`；正文精简仍可处理用户点名的索引文件。双目标顺序已明确则沿用，未明确才确认。

### 2. 澄清

标明「当前阶段：意图澄清」，用 [范围模板](../assets/docs-simplify-scope-ack-template.md) 输出公共六项；获本单元写前 `C` 才写。确认 hunk 时给出可定位边界；多文件批次列全路径。

### 3. 生成（改写）

按原则 A/B/C 改写：先重组结构，再删冗余，最后处理已确认的重复定义。固定模板保留章骨架；hunk 模式仅改确认片段。

用户要求跨文件去重，或当前单元存在疑似重复时，再围绕该事实搜索候选；需要时可扫全仓。候选列出源/目标、同义依据和拟处置，确认后只改已授权文件。无命中则处理文件内复述，不虚构真源。

四层业务 knowledge 引用先读 [knowledge-governance.md](../../../knowledge/knowledge-governance.md) 的引用边界；不得直接拼接跨层 HTTP，也不得链出允许层级。无 parent 用纯 ID。

### 4. 烤干

标明「当前阶段：烤干」，对照改前内容与 diff，完成 [质量清单](quality-checklist.md) 和 [受众要求](audience-and-language.md)。语义问题按 gates 停问；非语义修订及后续 simplify 遍按共享推进协议执行，不嵌套完整技能环。

### 5. 扩批（下一单元）

收敛后报告修改、验证、未决项，并给 `C/M/G/S/F` 动作。下一单元及 `F` 批量推进按 [单元推进协议](../../../references/unit-cycle-protocol.md) 执行。

## 不确定

仓内可核实的先查；仍不明的真源、范围或语义取舍保留原文，给推荐与数字选项。
