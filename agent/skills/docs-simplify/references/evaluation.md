# docs-simplify 评测

套件见 [evals.json](../evals/evals.json)，评分见 [grader.md](../agents/grader.md)。场景覆盖路由、授权、单文件/hunk/批次、约束与契约、SSOT、knowledge 和写后动作。

## 运行

用 [eval_case.py](../scripts/eval_case.py) 控制输入与快照；它不调用模型、不判断语义。每例使用新代理或独立会话，控制方持有套件、未来消息和评分资料。

1. 控制方执行 `init --suite <evals.json> --case <ID> --run-dir <新目录>`，创建 runtime、work 与 control。runtime 只含运行材料；work 只含本例夹具；control 不交给被测代理。
2. 执行 `next --run-dir <目录>`，只将返回的当前 `message`、`workdir` 和 `skill_path` 交给代理。限制它读取 runtime 和本例 work；不得提供整份套件、未来 `turns`、预期答案或其他用例。
3. 等待代理真实返回或停顿；保存本轮响应，再执行 `record --run-dir <目录> --response-file <响应文件> --agent-id <代理ID>`。驱动此时保存 work 快照。响应未返回前不调用下一轮；不让被测代理代写未来响应或代跑驱动。
4. 仅在记录完成后再次 `next`，把下一条消息通过同一代理的后续回合发送；重复至 `done`。不要把整段对话一次性交给代理自行模拟。每轮核对相应快照；需恢复旧授权的测试必须先观察原授权已实际生效。
5. 评分方另读完整用例、真实响应、控制记录和快照，逐断言评分。读取/检索断言须保存真实工具调用与结果，不能以自述替代；范围外文件比对字节，保留约束按语义等价判断，链接与锚点另检。

驱动命令通过 `python3` 执行，参数详见 `python3 scripts/eval_case.py --help`（相对技能目录）。控制记录是编排证据；它不能代替真实代理回合。被测代理的文件访问范围仍由执行环境与调度约束，不把目录分离声称为操作系统沙箱。

一次 smoke 可选代表场景；完整回归须逐例运行。记录用例 ID、被测版本/模型、代理 ID、已执行阶段、结果路径和未执行原因。禁止跨用例沿用授权；原始记录不得用后补模拟结果覆盖。

用例的授权措辞须与断言一致：测试写前停顿时明确“等 C 再改”；已确认真源不必重新询问。发现歧义时保留原评分和证据，修正版本后另起运行，不把原失败改判为通过。

## 验证层次

- 结构：JSON 可解析、ID 唯一、断言完整、夹具路径相对且无越界。
- 驱动：运行 `python3 -m unittest discover -s tests -p 'test_*.py'`（相对技能目录），验证消息逐轮交付、状态推进和快照。
- 行为：实际代理逐轮读取消息后产生的决策、写入与停顿；查看 [grader.md](../agents/grader.md) 的证据要求。

结构或驱动测试通过不代表技能行为通过；单次发送整段对话的脚本演练不能验证尚未获得未来信息时的授权门禁。技能 frontmatter 可另用 skill-creator 的 `quick_validate.py` 检查。当前脚本只服务评测，不自动改写业务正文。
