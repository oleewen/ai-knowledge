# docs-upgrade 合并规则

本文件定义分类与内容合并；执行顺序和版本见 [workflow.md](workflow.md)，确认时机见 [gates.md](gates.md)。

## 1. 角色

| 侧 | 保留内容 |
| --- | --- |
| 元库 `{meta}/{dir}/` | 目录骨架、模板、md 的 H2–H6 结构 |
| 本库 `文档目录` | 业务正文、实体、独有路径 |

## 2. 已改判定

整树先按 [版本范围](workflow.md#版本范围与推进) 选源路径，再对同相对路径统一换行为 `\n`、去掉行尾空白后比较：相等则跳过，不等则按 §3 分类。指定模式不以相等跳过，按 §7 判定。

## 3. 清单桶（脚本）

| 桶 | 条件 | 写盘策略 |
| --- | --- | --- |
| 新增骨架 | 元库有、本库无，且非排除项、未命中 §3.1 | `C` 后由 scaffold 复制 |
| 跳过 | 内容规范化后相同；缺失示例命中真实实例；已改非 md | 无动作；后两者注明原因 / 实例路径 |
| 结构重填 | 两边有、已改的 md，根级 DESIGN 除外 | Agent 按 §4–§5 处理 |
| 整文件覆盖 | 两边有、已改的根级 `DESIGN.md` | scaffold 先备份再整文件覆盖；版本字段遵守 workflow |
| 本库独有 | 元库无该路径 | 保留不删，仅报告 |

以下规则先于分类，并同时适用于指定模式：

| 路径 | 规则 |
| --- | --- |
| `knowledge-links.yaml` | 永不从元库覆盖或补入 |
| 根 `README-s.md` / `README-c.md` | 不作为额外目标写入；本库已有同名文件保留 |
| application 根 `README.md` | 对照元库 `README-s.md`，无该源时用 `README.md` |
| 顶层 `application-*` / `system-*`（除 `application-slots` / `system-slots`） | 遗留槽位硬忽略；整树另列「忽略遗留槽位」 |
| 软链文件、目录及其下路径 | 跳过且不跟随；整树另列「跳过软链」，指定模式拒绝该项 |
| slots 下非软链真文件（含 `changelogs/`） | 与普通路径同规则；软链目标仓同步归 `/docs-pull` |

### 3.1 整树缺失示例与真实实例

仅整树（含版本增量）对「元库有、本库无」执行；dry-run 与 apply 共用。指定模式不套用此去重。

| 对象 | 判定 |
| --- | --- |
| 示例文件 | `TYPE-EXAMPLE.md` 或 `TYPE-EXAMPLE-后缀.md`；本库对应父目录直接存在真实 `TYPE-*.md` 时，跳过该缺失示例 |
| 示例目录 | 路径含 `TYPE-EXAMPLE` 或 `TYPE-EXAMPLE-后缀` 目录；对应父目录存在 `TYPE-名称/TYPE-名称.md` 时，跳过该示例目录下全部缺失文件，含索引、README、子示例、非 md |
| 真实实例 | `TYPE-` 后名称非空且不含大写 `EXAMPLE`；实体是普通文件，路径和文件非软链；目录实例含与目录同名的 `.md`。只看名称与存在，不查正文或 frontmatter |
| 查找边界 | `TYPE` 为 `-EXAMPLE` 前完整前缀，区分大小写；只查同父目录，不递归、不跨目录。空目录、只有索引的目录、软链和 EXAMPLE 均不算 |

已有 `BL/BL-RETAIL.md` 可抑制缺失的 `BL/BL-EXAMPLE.md`；已有 `BD/BD-SALES/BD-SALES.md` 可抑制 `BD/BD-EXAMPLE/**`。非示例骨架仍补齐，已存在的示例仍按 §2 分类，不删除。

跳过桶逐文件列「同类实例已存在」及命中实体路径。这是规则无动作项，不是用户跳过待处理项，不单独阻断版本推进。

## 4. 非 Markdown

- 其它非 md：本库已有则不覆盖；元库新增、本库无则可 scaffold。§3 排除项优先。
- **元库模板无 H2–H6 的 md**：本库已有则整文件本库胜；本库缺失则 scaffold。此规则先于普通 md 重填，也适用于指定模式；根级 DESIGN 仍按整文件覆盖特例。

## 5. 结构重填（Agent）

以升级前正文为输入，以元库 H2–H6 为节序和标题骨架：

1. 同标题按去首尾空白后匹配，**不比较层级**。同名多节按出现序一对一；多余本库节为未落位，多余元库节保留模板。
2. 命中节填入本库正文，标题级采用元库该节级。正文内标题整节统一平移：最浅标题对齐到 `元库标题级 + 1`，更深标题保持相对差；最高 H6，溢出标题及其更深标题均落 H6，正文并入该 H6 节，不写 H7+。
3. 本库有而元库无同标题的节列为未落位，按下表写入；须先完成 [§6 确认](#6-确认粒度)，不得静默落位或丢弃。

| 未落位动作 | 写入形态 |
| --- | --- |
| 并入原父级 | 找升级前本库大纲的原父标题；骨架仍有同名父时挂其下：同标题子节合正文，否则新建子节。子级 `min(父级+1, 6)`，正文标题再按第 2 条平移 |
| 原父级消失 | 整节原样追加文末，不平移 |
| 改挂骨架父（仅逐项） | 用户选骨架父标题后，写入形态同并入原父级 |
| 追加文末 | 保留本库该节标题及正文层级，整节原样追加 |
| 跳过 | 该项不写入 |

`C` 后默认可先写已对齐节的中间稿，再补已确认未落位；也可等全部决完一次落盘。整树原文件已有 scaffold 备份；指定模式不强制备份，不能假定存在 `.docs-init`。处理中须保有升级前正文与大纲，避免中间稿覆盖后失去未落位内容或原父级依据。

## 6. 确认粒度

清单 / 总览 `C` 与单文件 `C` 语义相同，区别仅在范围。有未落位时，`C` 后提供三档策略；具体确认顺序、策略选项与 `M/S/F` 均见 [gates.md](gates.md#未落位策略)。合并形态只以 §5 为准。

## 7. 指定路径强制对齐（文件模式）

先按 [parameters.md](parameters.md#指定路径展开) 规范化并展开，再应用 §3 排除规则。逐项分类：

| 条件 | 动作 |
| --- | --- |
| 软链、软链下路径或遗留槽位 | 拒绝该项；软链实例同步提示 `/docs-pull` |
| 元库无对应路径（含两边都无；已按 README 映射） | 停止该项并报错，不猜替代；其余项可继续 |
| 本库无、元库有 | scaffold；不因已有同类实例跳过示例 |
| 两边有、根级 DESIGN | 整文件覆盖；保留本库版本语义，见 workflow |
| 两边有、其它 md | 先检查 §4 的无结构例外，再按 §5 强制重填；不因规范化相等而跳过 |
| 两边有、非 md | 不覆盖；标「指定但非 md：不覆盖」 |

由 Agent 在确认范围内写盘，不调用脚本 `--path`；备份与验收见 [workflow.md](workflow.md#指定路径执行)。
