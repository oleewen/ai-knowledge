# docs-upgrade 合并规则

与 [SKILL.md](../SKILL.md) P0 契约一致；实现时以此为准。

## 1. 角色

| 侧 | 胜出域 |
| --- | --- |
| 元库 `{meta}/{doc_dir}/` | 目录骨架、脚手架、示例模板、md 的 H2至H6 **结构** |
| 本库 `DOC_ROOT` | 业务正文、实体、日志、已改文件内容、独有路径 |

## 2. 已改判定

对同相对路径：去掉行尾空白、统一 `\n` 后比较内容。

- 相等 → **跳过**
- 不等 → **已改**（md 进结构重填；非 md 见 §4）

## 3. 四桶（脚本清单）

| 桶 | 条件 | 写盘策略 |
| --- | --- | --- |
| 新增骨架 | 元库有、本库无，且非排除项 | 一批 `C` 后由 `--apply-scaffold` 复制 |
| 跳过 | 两边规范化后相同 | 无动作 |
| 结构重填 | 两边有、已改、且为 `.md` | Agent：元库 H2至H6 为骨；同标题填本库正文（见 §5） |
| 本库独有 | 本库有、元库无该路径 | **保留不删**；清单注明 |

排除（永不从元库装入目标）：`knowledge-links.yaml`（本库保活，不作骨架覆盖源）；以及 `README-s.md` / `README-c.md`（不作为目标文件名写入，见 README 映射）。根级 `CONTRIBUTING.md` **按普通 md** 进四桶（本无则 scaffold；已改则结构重填）。

**联邦相关**：

| 规则 | 行为 |
| --- | --- |
| 顶层遗留 `application-*` / `system-*`（**不含** `application-slots` / `system-slots`） | 硬忽略；清单「忽略遗留槽位」 |
| 凡软链（文件或目录；路径自身或祖先） | **跳过**不跟随；清单「跳过软链」；禁止 scaffold/重填 |
| `application-slots/`、`system-slots/` 下非软链真文件 | **进入**四桶 / 结构重填（与普通路径同） |
| `application-slots/changelogs/**`、`system-slots/changelogs/**` | 本无 → 新增骨架；本有 → 跳过并标「changelogs·本库胜」（不进结构重填；文件模式强制也不破） |
| 槽位实例内容（软链目标仓） | 归 `/docs-pull`，本技能不跟随 |

application 的 README 映射：本库 `README.md` 对照元库 `README-s.md`（若无则 `README.md`）；不把 `README-c.md`/`README-s.md` 作为额外目标文件名写入（除非本库已有同名）。

## 4. 非 Markdown

- `knowledge-links.yaml`：**永不**被元库覆盖
- 其它非 md（在 `DOC_ROOT` 内）：已改 → 本库胜（清单记跳过覆盖）；元库新增且本库无 → 可进新增骨架
- 无 H2至H6 的 md：整文件本库胜；仅当本库无该路径时作新增骨架

## 5. 结构重填（Agent）

1. 以元库 md 的 H2至H6 为节序与标题骨架（元库结构）
2. **同标题**匹配（去首尾空白；**不比层级**）。同名多节按出现序一对一：第 i 个本库同名节 ↔ 第 i 个元库同名节；多出的本库节 → 未落位；多出的元库节 → 留空模板节
3. 命中 → 用本库该节**正文**填入元库骨架位；**标题层级锚 = 元库该节级**
4. 正文自带标题 → **整节统一平移**：最浅标题对齐到 `元库标题级+1`，更深保持相对差（例：元库标题 H2，正文原 `## 甲` / `#### 乙` → `### 甲` / `##### 乙`）。算出的级 **封顶 H6**：相对差能保则保；不能则该标题与其下更深标题均落为 H6，正文并入该 H6 节（不写 H7+）
5. 元库有、本库无 → 保留元库节（新模板节）
6. 本库有、元库无同标题 → **未落位**，不得静默写入。一律逐项确认（见 §6 / [gates.md](gates.md)）：挂靠骨架某标题 / 追加文末 / 跳过。根级 `CONTRIBUTING.md` 与普通 md **同规则**。轻流程 `S` 不是「全跳过未落位」
7. 挂靠：整节写入所选父标题下——子标题级 = min(父级+1, 6)（保留未落位节名）+ 正文再相对该子标题级按第 4 条平移（含 H6 封顶）
8. 追加文末：整节原样追加（保留本库原标题层级与正文内层级，不做平移）
9. 全部未落位决完前，可先落「已对齐节」的中间稿，或等未落位决完一次落盘——默认：**对齐节可先写入**，未落位确认后再补写，避免长会话丢进度；备份已在 scaffold 步覆盖原文件

## 6. 确认粒度

- 清单/总览 `C` 与单文件 `C` **同语义**：执行全部可处理项（整树：新增骨架 + 结构重填；文件：强制重填 / scaffold）；对齐节按 §5 元库结构重填；**未落位算进 `C` 流程**，且每条须人回：挂靠 / 追加文末 / 跳过
- `M`：改参数/路径名单，或下钻到单文件
- 本库独有文件：只报告，不删

## 7. 指定路径强制对齐（文件模式）

与整树互斥。输入与展开见 [parameters.md](parameters.md)；流程见 [workflow.md](workflow.md)。不依赖 `@` 前缀。

对规范化后每条路径：

| 条件 | 动作 |
| --- | --- |
| 顶层遗留 `application-*` / `system-*`（非 `*-slots`） | **拒绝**该条 |
| 路径为软链或落在软链下 | **拒绝**该条；提示实例同步用 `/docs-pull` |
| `*-slots/changelogs/**` 且本库已有 | **整文件本库胜**（不强制重填）；总览注明 |
| `*-slots/changelogs/**` 且本库无、元库有 | **scaffold**（须总览或该文件 `C`） |
| 元库无对应路径（README 映射后仍无） | **硬停该条**（报错；不猜替代）；其余路径可继续 |
| 两边都无 | **硬停该条** |
| 本库无、元库有 | **scaffold** 该路径（须总览或该文件 `C`）；Agent 复制，不经脚本 `--path` |
| 两边有、且为 `.md`（非 changelogs 特例） | **强制结构重填**（破 §2「跳过」；契约同 §5） |
| 两边有、非 `.md` | **不覆盖**；清单标「指定但非 md：不覆盖」 |

排除项仍生效：不把 `knowledge-links.yaml` 当骨架覆盖目标。根级 `CONTRIBUTING.md` 与普通 md 同（强制重填 / scaffold；未落位逐项见 §5–§6）。

文件模式不强制 `.docs-init` 备份。
