# docs-upgrade：brainstorming 式前置（预检）

意图不清、多策略取舍、或步骤 3 大范围同步前需确认范围时读本文件。说明何时走快路径、何时做预检、以及写盘前的 HARD-GATE 条件。

本页借用 brainstorming 的**机制**（上下文探索、分步提问、方案比选、门禁），**不是** superpowers 中「先写设计文档到 `docs/superpowers/specs/` 再实现」的完整 brainstorming 工作流。

---

## 何时用「预检」、何时走快路径

| 情形 | 建议 |
|------|------|
| 用户已给出明确路径 + 明确替换/改写意图（含替换简写） | **快路径**：按 [../SKILL.md](../SKILL.md) 主流程执行，不必先做长对话。 |
| 无路径、意图模糊、或「统一/专业化/对齐」但未说明范围与标准 | **预检**：先探索上下文，**一次只问一个**关键问题，再锁定目标。 |
| 可能有多策略（仅标题 vs 全文、保守替换 vs 整段重写） | **预检**：给出 **2～3 种做法**、利弊与推荐，用户确认后再做步骤 2。 |
| 链式/关键词同步前：命中过多、目录过大、概念是否同一存疑 | **预检 + HARD-GATE**：见下文，确认后再进入步骤 3。 |

---

## HARD-GATE（在本技能中的含义）

- **不是**：禁止任何写入，直到产出独立设计规格文档。
- **而是**：在**高风险扩展**之前必须得到确认——主要指：
  - **大批量或跨目录**的术语/表述统一（含关键词检索命中爆炸）；
  - **链式深度扩展**或「所有提到 X 的地方」类需求尚未界定批次与排除目录；
  - **多段文本是否同一概念**不确定时的批量对齐。

未通过确认前：**不进行**步骤 3 中的大范围同步替换，或仅完成已确认批次内的修改。

---

## 与主流程的对应关系

1. **步骤 1（锁定目标）**  
   - 预检：读相关文件/索引，澄清「改什么、改到哪一文件」；多候选时列出选项，必要时 **单问** 缩小范围。

2. **步骤 2（主修改）**  
   - 预检：若存在多种实现方式，先 **2～3 方案 + 推荐**，再动手。

3. **步骤 3（关联与语义同步）**  
   - **同步前闸门**：对照 [gotchas.md](../gotchas.md)（短词高命中、过度统一、一层不够等）。必要时先确认批次、路径边界、是否扩展关键词轮次，再执行引用链与关键词策略。  
   - 技术细则仍见 [related-doc-discovery.md](related-doc-discovery.md)、[semantic-keyword-discovery.md](semantic-keyword-discovery.md)。

4. **步骤 5（不确定项门禁）**  
   - 复杂决策可拆成 **多轮**，每轮 **一个**编号题或一个主题，避免单条消息堆砌过多决策点（与「一次一问」一致）。

---

## 操作要点（简）

- **上下文探索**：优先基于仓库内真实路径与内容，不编造事实；无法在仓库内核实的内容保持 [../SKILL.md](../SKILL.md)「须由用户决策的情形」与步骤 5。
- **分步提问**：同一轮对话中，优先 **一次一个问题**；若必须多选项，用编号选项并仍可附简短推荐。
- **方案推荐**：给出推荐时简述理由；用户明确选择后再写入或再扩展同步范围。
