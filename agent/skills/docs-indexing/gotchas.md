# docs-indexing 常见陷阱

补充 SKILL.md 门禁与约束的场景说明——遇到具体问题时来这里查。

---

## 参数门禁相关

**"没有历史日志，我就自动选全量吧"**
这是最常见的越权行为。无论是自动选全量还是自动选增量，都违反了门禁原则。正确做法：说明增量前提不满足，请用户在「全量」与「中止」之间确认。

**"用户选了预设 A，我就直接执行了"**
选预设只是用户表达了倾向，不等于确认。选中预设后仍须复述完整参数（mode / depth / output / since），请用户最终确认再执行。

**"深度太大了，我帮用户降到 2 吧"**
深度是用户的决策，不是 Agent 的优化项。可以告知深度 3 的成本，但不能替用户降级。

**`--since` 和 `--output` 的默认值静默采用**
候选时间戳与默认路径须展示给用户确认（或用户显式给出字面量）后再写入命令。"默认"不等于"不需要确认"。

**增量基线时间戳来源混淆**
索引增量的**首选**基线是 `INDEXING-LOG.md` 主表**第一行**的 `indexing_finished_ms`；迁移前文件可回退为文内最后一次 `<!-- sdx-indexing:indexing_finished_ms=... -->`。
`CHANGE-LOG.md` 文末的 `docs-change:baseline_time_ms` 是 **docs-change** 的采集基线，两者不可混用。

## 扫描与采集相关

**深度 3 抽样跳读**
用户确认了 `depth=3` 就是要最大化覆盖。不能只读每模块少量示例文件，或跳过"看起来差不多"的同级文件。须在排除规则内系统遍历；无法读完的路径必须在 §八 明示。详见 [reference/scan-spec.md](reference/scan-spec.md)「深度 3 应读尽读准则」。

**把未读文件写成已索引内容**
零幻觉原则的核心：只索引实际读取的内容。未读路径标注 `[未索引]` 并说明原因，归入 §八。猜测的内容一旦写入索引，会污染下游所有依赖它的技能。

**增量模式清空未变更章节**
增量更新只合并变更文件对应的条目，未变更部分保持原样。不要重写整个 INDEX_GUIDE.md——那样会丢失上次精读的成果。

**索引了构建产物目录**
`target/`、`build/`、`node_modules/` 等须严格排除。这些目录体积大、内容无意义，会让索引膨胀并掩盖真正的业务代码。

**同一文件归入多个章节**
每个文件只归入一个最匹配的章节，跨章节引用以超链接形式体现（MECE 原则）。重复内容会让索引失去权威性。

## 九章结构生成相关

**留有空章节**
确实无内容的小节标注 `[未索引]` 并说明原因（如"当前项目无消息队列组件"），归入 §八排除列表，不留空白。空章节会让读者怀疑索引是否完整。

**条目信息密度不达标**
每条目 15-30 字，包含功能描述、关键属性或路径。"用户服务"、"订单模块"这类空洞标签没有导航价值。

**路径使用绝对路径**
一律使用项目根相对路径（如 `src/main/java/com/example/Service.java`），不用 `/Users/xxx/...` 或 `../src/...`。绝对路径在其他机器上无法点击。

**版本号、配置值凭印象填写**
§七配置中心的版本号或配置值必须来自实际读取的 `pom.xml`、`application.yml` 等文件。猜测的版本号比没有版本号更危险。

## 输出与日志相关

**未写操作日志**
每次成功写 `INDEX_GUIDE` 后必须向 `changelogs/INDEXING-LOG.md` 主表**插入一行**（最新在上）。不写入则下次增量无有效主表锚点；迁移前仍可能依赖文内旧 HTML 注释回退。

**主表行缺失关键列**
`indexing_finished_ms`、`mode`、`depth`、`output_path` 等须完整；主表见 [reference/indexing-log-spec.md](reference/indexing-log-spec.md)；缺少 `indexing_finished_ms` 会无法作增量基线。

**输出路径优先级混淆**
优先级：用户指定 > `./{DOC_DIR}/` > `./doc/` > `./INDEX_GUIDE.md`。若使用默认值，须将解析结果展示给用户确认后再写入。

## 与上下游协作相关

**增量模式跳过 docs-change**
增量模式必须先通过 `docs-change` 维护 `CHANGE-LOG.md`，以变更文件列表驱动扫描范围。直接扫描全部文件就失去了增量的意义。

**与 agent-guide 产出的目录树矛盾**
agent-guide 生成 README 时以本 INDEX §二为唯一来源。本 Skill 更新 §二后需通知 agent-guide 同步，保持两处一致。

## 快速自查清单

- [ ] 扫描模式与深度已由用户确认，非 Agent 默认定参
- [ ] `--since`、默认 `--output` 等已展示并确认（或用户显式给出）
- [ ] 九章均有实质内容，无空章节（空内容标注 `[未索引]`）
- [ ] 每条目 15-30 字，无占位符和空话
- [ ] 所有路径为项目根相对路径，可访问
- [ ] 版本号、配置值来自实际读取的文件
- [ ] 每个文件只归入一个章节（MECE）
- [ ] 主表行已写入 `changelogs/INDEXING-LOG.md`（或同意旧式+回退仅迁移期使用）
- [ ] 增量模式未清空未变更章节
- [ ] 构建产物目录已排除
- [ ] 未读内容未写成已核实事实（零幻觉）
- [ ] 若深度为 3：已按应读尽读准则遍历，无抽样跳读
