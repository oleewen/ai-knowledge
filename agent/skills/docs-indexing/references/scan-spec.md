# 扫描执行规范

深度、模式、过滤、增量、日志、错误处理。

---

## 深度级别

| 级别 | 名称 | 扫描范围 | 适用场景 |
|------|------|----------|----------|
| 1 | 拓扑扫描 | 目录结构、主要模块、元数据 | 快速概览、大型仓库初扫 |
| 2 | 结构分析 | +类名/函数名/注释、接口定义、关键配置 | 日常索引、增量更新 |
| 3 | 精读提取 | 在排除规则内**目录与文件应读尽读**，**尽量读全**可读文本；据此建立**尽可能多的**索引条目与交叉引用 | 权威全量地图、深度 Onboarding、RAG 证据最大化 |

### 各深度扫描对象

| 深度 | 扫描对象 | 典型文件类型 |
|------|----------|--------------|
| 1（拓扑） | 目录结构、`pom.xml`/`build.gradle`、`README`、`*.yml`/`*.yaml` | 配置/元数据 |
| 2（结构） | +`*.java`/`*.kt` 类名/函数名/注释、接口定义、`*.xml` Mapper | 源码结构 |
| 3（精读） | 在 1/2 基础上，对纳入扫描集的文件**完整读取**（或按文件类型规定的最大可读范围），覆盖业务逻辑、分支、注释、SQL、配置与文档正文 | 源码与文档全文为主 |

### 深度 3：应读尽读

确认 `depth=3` 时：

1. **目录**：过滤外全树遍历；不读的路径须在 §八 写原因  
2. **文件**：同类文本优先整文件读；超限分段须注明范围，并尽量覆盖面（符号、配置、逻辑）  
3. **条目**：MECE 下尽量多行；禁止「每目录少量样本」糊弄  
4. **相对 1/2**：3 = 允许范围内读全写满；非「多读一点」；未读勿当事实

## 模式逻辑

### full（全量）

忽略历史记录，全量扫描代码库。适用于首次索引或需要重建索引时。

### incremental（增量）

基于 `INDEXING-LOG.md` **主表第一行**的 `indexing_finished_ms` 作为时间锚点（**最新在上**；迁移期可回退文内最后一条 `<!-- sdx-indexing:indexing_finished_ms=... -->`），仅处理变更文件。详见 [indexing-log-spec.md](indexing-log-spec.md)。

1. 从主表取锚点，或回退到 HTML 注释
2. 仅扫描基线时间之后变更的文件
3. 对已有章节：合并更新，不清空未变更部分
4. 对新增文件：归入对应章节
5. 对删除文件：从索引中移除相关条目
6. 最终结构须与全量索引保持一致

无有效基线时，须向用户说明增量前提不满足，请用户确认改走全量或中止，**不得**静默自动全量；辅助脚本在 incremental 下无基线时**非 0 退出**。

## 路径解析

- 基于项目根目录的相对路径
- 输出路径优先级：用户指定 > `./{DOC_DIR}/INDEX-GUIDE.md` > `./doc/INDEX-GUIDE.md` > `./INDEX-GUIDE.md`

## 文件过滤

自动忽略以下路径：

| 排除模式 | 原因 |
|----------|------|
| `target/`、`build/` | 构建产物 |
| `.git/` | 版本控制 |
| `node_modules/` | 前端依赖 |
| `*.log` | 运行时日志 |
| `*.class`、`*.jar` | 二进制文件 |
| `.idea/`、`.vscode/` | IDE 配置 |

---

## 日志

INDEX 成功后向 `INDEXING-LOG` **主表**插顶行（[indexing-log-spec.md](indexing-log-spec.md)、`indexing_log.py`；`indexing.sh` 调 append）。

## 错误处理

| 场景 | 处理 |
|------|------|
| 无历史日志 | 说明增量前提不满足，请用户确认改走全量或中止 |
| 变更驱动数据缺失（增量联动） | 须配合 docs-change 与 `CHANGE-LOG.md`；详见 Skill 风险控制与推进协议 |
| 输出目录不存在 | 自动创建目录 |
| 文件不可读 | 跳过并记录到索引边界（§八） |
| 增量基线无效 | 说明基线无效，请用户确认改走全量或中止 |
