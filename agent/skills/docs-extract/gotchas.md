# docs-extract 常见陷阱

技能正文见 [SKILL.md](SKILL.md)；提炼规范见 [reference/extract-spec.md](reference/extract-spec.md)。

---

## 关键词附录

**附录节不存在时静默跳过**：`## 文档关键词` 节不存在时必须终止并提示用户补充，不能用 overview 章节标题自动推断关键词——自动推断的关键词过于通用，会导致大量弱相关段落命中。

**关键词过于宽泛**：如果关键词包含「系统」「数据」「管理」等高频通用词，几乎所有段落都会命中，失去筛选意义。遇到命中段落异常多时须警告用户收窄关键词。

**关键词与应用业务脱节**：关键词应反映该应用的实际业务术语（如「理赔」「保单」「核保」），而非通用技术词汇。提炼前可提示用户确认关键词是否准确覆盖业务语境。

## 段落筛选

**把 overview 自身内容当源文件扫描**：步骤 2 只扫描 `--sources` 指定的文件，不扫描 `--overview` 目标文件本身，否则会把 overview 已有内容循环写入。

**代码块内容误触发**：代码块中的注释或变量名可能命中关键词，但通常不含业务知识。提炼时须判断命中段落是否为代码块，代码块内容不提炼为业务知识摘要。

**标题行单独命中**：Markdown 标题行（`# 业务规则`）可能单独命中关键词，但标题本身不含实质内容。标题行不单独提炼，跟随其后正文段落处理。

**短段落误命中**：单行的「见上文」「如下所示」等过渡句可能命中关键词。短段落（< 20 词）须至少命中 2 个关键词才进入候选池。

## 提炼写入

**整段复制源文件内容**：第三列应是提炼后的业务知识摘要，不是源文件段落的粘贴。若命中段落内容很长，须提炼核心要点写入，细节保留在源文件。

**变动标识遗漏**：每次写入第三列时须准确标注 A/U/D：
- 原为 `—` 或空 → 写入内容 → 标 `**[A]**`
- 原有内容 → 内容有实质变化 → 标 `**[U]**`
- 原有内容 → 本次应删除 → 标 `**[D]**`，清空内容
- 原有内容 → 本次无变化 → 保持原内容，不加标注

**无命中章节被清空**：无命中段落的章节须保持原内容不变，不能写 `—` 覆盖已有内容，也不能留空。

**未读「应填内容 + 产出建议」就直接写入**：每节写入前须先读副标题链接对应章节的「应填内容」和「产出建议」注释，了解该节期望的内容格式，再提炼写入。

**部分写入失败后继续**：步骤 3 任意章节写入失败时须整体回滚，不做部分落盘，避免 overview 处于不一致状态。

## 源文件处理

**目录递归展开遗漏隐藏文件**：递归展开目录时，以 `.` 开头的隐藏文件和目录默认跳过，除非用户明确指定。

**二进制文件误处理**：图片、PDF、Excel 等二进制文件无法按段落切分，遇到时跳过并在预览中提示用户。

**源文件路径不存在**：步骤 0 须校验所有 `--sources` 路径存在性，任一路径不存在时终止并列出无效路径，不静默跳过。

## 快速自查清单

- [ ] `--sources` 所有路径均已校验存在
- [ ] `--overview` 路径存在，且包含「章节 → 文档关键词」附录节
- [ ] 步骤 2 未将 overview 自身纳入扫描范围
- [ ] 命中段落数量合理（无异常多命中），关键词未过于宽泛
- [ ] 代码块内容未被提炼为业务知识
- [ ] 只有有命中段落的章节被更新，无命中章节保持原样
- [ ] 每节写入前已读对应章节「应填内容 + 产出建议」
- [ ] 第三列内容为提炼摘要，非源文件整段复制
- [ ] 变动标识（A/U/D）准确标注，无遗漏
- [ ] 写入失败时已整体回滚，未做部分落盘
