# docs-extract 提炼规范

本文件定义来源解析与提炼规则；执行时机见 [workflow.md](workflow.md)，路径与表行见 [knowledge-layout.md](../../../references/knowledge-layout.md)。

## 关键词附录格式

读取目标实际存在的非空关键词附录，兼容两种格式，不因格式差异要求用户重新选词或改写附录：

- 标准模板及 `docs-tag` 输出：`## 附录` 下 `### 文档关键词` 的 YAML `keywords` 字符串列表；旧式 `<!-- spec-tags … -->` 词表也可读取。词表是全局筛选依据，命中后的章节归属按目标行要求和业务语义判断。
- 已有章节映射表：`## 文档关键词` 下的「章节 / 关键词」表。按表中映射筛选；章节须对应目标中的实际章节，不能套用其他层词表。

缺失、空值、格式无法解析、多个词表相互冲突，或命中要点无法归属目标行时，先说明具体缺口并澄清；不自动补词或迁移格式。关键词维护属于独立范围，不能为扩大本轮命中而自行改附录。

标准 YAML 格式示例（不是默认词表）：

````markdown
## 附录

### 文档关键词

```yaml
keywords:
  - 审批
  - 退款
```
````

## sources 归一化

| 条目 | 处理 |
| --- | --- |
| 已存在的文件 | 读取为一个文本块，保留文件与段落位置供会话核对 |
| 已存在的目录 | 递归枚举普通文本文件；默认跳过隐藏路径、二进制及符号链接；用户明确指定的隐藏路径或链接另行解析范围 |
| 明确的内联文本 | 直接分段，不做文件存在性校验 |
| 疑似路径但不存在 | 报出缺失项并澄清，不当成正文，也不报告为“无命中” |

按解析后的真实路径排除目标 overview 自身、去除重复文件。显式链接目标若指回已访问目录，不重复递归；超出已确认来源范围先澄清。记录跳过或不可读项；读取不完整时说明覆盖范围，不得宣称全量已扫描。

## 段落筛选

1. 按空行切段；标题作为后文上下文，不独立产出。代码围栏整块识别，不从代码或 DDL 中凑业务命中。
2. 按附录关键词匹配，不区分大小写、允许部分匹配；仍须核对业务语义。命中只是候选，不是已核实知识。
3. 至少一个关键词即可形成候选，短句也可承载完整业务约束；不以分词长度或固定命中数量淘汰有效事实。偶然字面命中但无业务关联的段落排除，并说明原因。
4. 章节映射表约束候选范围，全局词表按目标行要求与业务语义定位。命中密度可辅助排序，不能替代语义归属或在冲突时自动决胜。多个副标题行按各自要求定位，不把同一要点复制到全部行；无法确定时列出候选落点并澄清。

## 提炼写入

共享规则：[federation-spec.md](../../docs-distill/references/federation-spec.md)「规则（第三列）」。extract 按命中批次处理，不能照搬 distill 的全行覆盖动作。

1. 读命中行的「应填内容 + 产出建议」。比对副标题链接的锚点小节；不可读时回退主标题链接整章。两者均不可读则列为待核实，不推断“未覆盖”或写成 `[A]`。
2. 比对知识正文，跳过已覆盖/语义等价要点；仅提炼新 delta。无命中或无新 delta 时保留第三列原样，不以 `—` 清空旧待归档内容。
3. 旧第三列不作为“正文已覆盖”的证据，但属于待保留的工作内容。保留与本轮无关的旧项；新要点已在旧列待归档时不重复追加。新旧冲突或需替换旧项时，展示差异并确认。
4. 按共享规则标记 A/U/D。`[D]` 须有明确的废止依据或用户确认，写删除说明，交归档流程处理；来源未提及、关键词未命中都不是删除依据。
5. 摘要须适合目标层；不粘贴 API 表、DDL 或原文整段。来源定位留在会话核对记录，第三列不写来源脚注；引用遵守 [knowledge-governance.md](../../../knowledge/knowledge-governance.md)「业务 knowledge 引用边界」。

## 自检

按 [quality-checklist.md](quality-checklist.md) 核对命中、正文依据、旧项保留与实际 diff；无新 delta 就不写文件。
