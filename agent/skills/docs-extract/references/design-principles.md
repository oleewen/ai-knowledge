# docs-extract 设计原则

与 [anti-patterns.md](anti-patterns.md) 互补；**操作层易错点**仍见 [../gotchas.md](../gotchas.md)。

---

## 原则

1. **关键词附录为真源**：无附录或附录无效须停机补齐，不得用章节标题「猜」关键词。
2. **强相关才写入**：弱相关、代码块噪声、标题单行等按 extract-spec 与 gotchas 过滤。
3. **先读后写**：读目标节「应填内容 + 产出建议」与现有第三列，再写 A/U/D。
4. **无命中不改**：无命中段落的小节保持原样，禁止用 `—` 覆盖已有内容。
5. **第三列无出处脚注**：追溯放会话 spec 或确认材料。
6. **原子落盘**：4.3 失败则整体回滚，禁止半篇 overview 已提交状态。
7. **风险先预览**：HARD-GATE 场景默认 `dry-run`。
