# 提炼规范

docs-extract 的关键词附录格式、段落筛选规则与提炼写入规范。

---

## 关键词附录格式

overview 文件末尾须包含「章节 → 文档关键词」附录节，格式如下：

```markdown
## 文档关键词

| 章节 | 关键词 |

| 业务概述 | 业务目标, 核心价值, 业务背景, 适用场景 |

| 商业模式 | 商业模式, 盈利, 定价, 收费 |

```

**说明**：
- 关键词列表由用户手动维护，反映该 overview 所属应用的业务语境
- 关键词应使用应用实际使用的业务术语，而非通用词汇
- 同一关键词可出现在多个章节（段落会归属到命中密度最高的章节）
- 关键词附录节标题固定为 `## 文档关键词`

## 段落筛选规则

### 段落切分

- 以连续空行（`\n\n`）为段落分隔符
- Markdown 标题行（`#` 开头）单独作为一个段落单元，不与正文合并
- 代码块（` ``` ` 包裹）作为整体处理，不拆分内部行

### 命中密度计算

对每个段落，按以下方式计算与各章节的相关度：

1. 将段落文本分词（按空格、标点切分）
2. 统计段落中出现的关键词数量（不区分大小写，支持部分匹配）
3. 命中密度 = 命中关键词数 / 段落总词数
4. 命中密度 > 0（即至少命中一个关键词）的段落进入候选池
5. 段落归属到命中密度最高的章节；若多章节命中密度相同，归属到五视角顺序靠前的章节

### 阈值说明

- 默认阈值：至少命中 **1 个关键词**
- 短段落（< 20 词）：至少命中 **2 个关键词**，避免偶发词汇误触发
- 标题行：不单独参与筛选，跟随其后正文段落的归属

## 提炼写入规范

提炼逻辑与 `docs-distill` 步骤 3 完全对齐：

### 写入步骤

1. 读取 overview 五架构视角知识索引表
2. 逐条读取副标题列文件链接对应章节的「应填内容」和「产出建议」注释，了解该节期望的内容格式
3. 从该章节的命中段落中提炼有效信息，按要求改写为适合系统库的表达
4. 判断变动类型并写入第三列：
   - 原第三列为 `—` 或空：标注 `**[A]**`（新增）
   - 原第三列有内容且本次有实质变化：标注 `**[U]**`（变更）
   - 原第三列有内容但本次应删除：标注 `**[D]**`（删除，清空内容）
   - 原第三列有内容且本次无变化：保持原内容，不加标注
5. 无命中段落的章节：保持原内容不变，不写 `—`，不做任何修改

### 撰写规则

- **先读再写**：先读副标题链接对应章节的「应填内容 + 产出建议」，再提炼写入
- **完整内容**：第三列可写多段、列表、小表格，是该应用的完整知识快照
- **不整段复制**：提炼有效信息，改写为适合系统库的表达，不粘贴源文件原始段落
- **强相关优先**：命中密度低的段落（仅 1 个关键词且段落较长）提炼时须更保守，只提取核心信息
- **无内容时不强填**：命中段落中无法提炼出有效信息时，不强行填充，保持原内容

---

## 质量自检

- 关键词附录节存在且非空
- 命中段落均来自源文件，未混入 overview 自身内容
- 只有有命中段落的章节被更新，无命中章节保持原样
- 变动标识（A/U/D）准确反映本次提炼的实际变化
- 第三列内容为提炼摘要，非源文件整段复制
- 应用侧细节（接口 DDL、代码片段、原始用户故事等）未出现在第三列
