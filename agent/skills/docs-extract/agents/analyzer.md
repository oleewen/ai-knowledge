# docs-extract 失败分析器

根据实际轨迹与产物定位最小修复，不因一次失败增加全局限制。

## 输入

失败用例 ID、[断言](../evals/evals.json)、实际回复/工具轨迹及前后文件；先读 [SKILL.md](../SKILL.md)，再按失败位置读取 gates、workflow 或 extract-spec。

## 输出

| 项 | 要求 |
| --- | --- |
| 失败模式 | 路由、确认/范围、扫描/筛选、正文比对、delta/旧项、引用边界、落盘/恢复、证据不足 |
| 证据 | 用例/断言 ID + 回复原句、工具结果或文件 diff |
| 根因 | 区分规则缺失、规则冲突、执行偏离和测试输入不足 |
| 最小修复 | P0/P1/P2、目标文件、行为影响；只修已证实问题 |
| 回归 | 至少一个能复现失败的案例，含预期产物或不变量 |

先回放失败例，再覆盖受影响分支。路由问题成对验证 extract 与 distill/archive；证据不足不得计为行为通过。
