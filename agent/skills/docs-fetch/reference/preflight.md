# docs-fetch 预检与分步确认

本页说明 Agent 在执行 `docs-fetch` 时**何时必须停下问用户**、**按什么顺序问**、以及**写盘闸门（HARD-GATE）**。目的与 superpowers「brainstorming」不同：不产出设计 spec，只在**高风险或歧义**时协作澄清，避免误同步。

---

## 写盘闸门（HARD-GATE）

**在真正改写**应用知识库根目录下 `applications/app-{APPNAME}/` **之前**（即非 `--dry-run` 的拉取与 rsync），须同时满足：

1. **目标应用已明确**：`--app` 已给出，或用户已从列表中选定唯一应用。
2. **目标分支已明确**：`--branch` 已给出，或自动探测（`main` → `master`）已成功，或用户已确认使用某一分支。
3. **manifest 可读且 `repo_url` 非空**；否则终止并见 [gotchas.md](../gotchas.md)。
4. 若将使用 **`--force`** 或存在**大范围覆盖**风险（例如用户表达「全部覆盖」「不管本地差异」），须**一句显式确认**后再执行。

**允许跳过冗长确认的情况**：用户已明确给出 `--app`、`--branch`，且无 `--force`/冲突语义，可直接执行（或先 `--dry-run` 再实跑，由用户一句话指定）。

---

## 何时必须停下（不猜）

| 情况 | 动作 |
|------|------|
| 未指定 `--app` 且存在 **多个** 已注册应用 | 列出候选，**每次只问一个**：先选定应用，再谈分支。 |
| `git clone` / 指定分支失败 | 提示失败原因，列出远端可用分支（若可获取），给出选项，**不自动换分支**除非用户明确授权。 |
| `main` 与 `master` 均不存在 | 终止，请用户指定 `--branch`。 |
| `repo_url` 缺失或为空 | 终止，请用户补 manifest，见 gotchas。 |
| 用户意图不清（例如「同步一下」但多应用且未点名） | 先列出应用再问选哪一个。 |

细节与恢复步骤见 [gotchas.md](../gotchas.md)。

## 分步提问顺序（与四步工作流对齐）

与 [SKILL.md](../SKILL.md) 步骤一致，**同一时刻只推进一个问题**。

### 对应步骤 1：应用与 manifest

1. 若需用户选应用：展示列表 → 用户选定 `{APPNAME}` → 再读 manifest。
2. 向用户**复述**将使用的 `repo_url`、`docs_root`、`app_id`（可表格一行），避免张冠李戴。
3. 分支优先级已在 SKILL 中定义：`--branch` > manifest `default_branch` > 自动探测；探测失败则进入「分支选项」见下节。

### 对应步骤 2：执行方式

- 若用户未要求实跑，可建议：「是否先 `--dry-run` 再正式执行？」（是/否）。
- 实跑前（HARD-GATE）：**简短确认**——例如：「将以分支 `{branch}` 从 `{repo_url}` 同步到 `applications/app-{APPNAME}/`，是否继续？」

### 对应步骤 3～4

- 脚本失败：不要宣称完成；changelog 规则见 SKILL 与 gotchas。
- 成功后：输出摘要（分支、short commit、增删改统计）。

## 分支与冲突时的选项示例（可多选呈现）

**分支不存在或 clone 失败时**（示例文案，按需替换占位符）：

- **A**：你指定 `--branch <名称>` 后重试。
- **B**：先 `--dry-run` 用你指定的分支看计划操作。
- **C**：中止，你先检查远端仓库或网络。

**多应用且用户只说「全部同步」时**：

- 明确是否**按顺序逐个应用执行**（每个应用仍各过一次写盘确认），或**只对某一个应用执行**；不要默认「静默扫全部」除非用户明确授权。

---

## 与「完整 brainstorming」的边界

若用户目标超出「把已登记应用的远端文档拉到联邦镜像」（例如重组联邦目录、改多仓合并策略、重新定义 `docs_root` 约定），应先完成需求澄清或设计任务，再回到本技能的参数与 manifest 事实。**本页不替代**应用级 SDD 或仓库级设计文档。

## 快速自检（执行前）

- [ ] 应用与分支已锁定或通过 HARD-GATE。
- [ ] 非 dry-run 实跑已获用户确认（若属于上文「必须停下」情形）。
- [ ] 已阅读或与 [gotchas.md](../gotchas.md) 对照：changelog 备份、manifest 保护、fetch-log 追加。
