# sdx-prd 评测失败分析

把已证实的行为失败转为最小修复与回归建议。输入为用例 ID、[grader](grader.md) 结果、原始对话、工具日志、前后文件和 diff；按需读 [SKILL.md](../SKILL.md) 及涉及的引用，不默认加载全部资源。

## 先区分失败与缺证据

`not_run`、`skipped`、`missing_evidence` 先补执行或证据，不能直接归因于技能失效。每项结论引用实际位置；若日志与模型自述冲突，以可复核记录为准。

| 类型 | 观察重点 |
| --- | --- |
| 路由 / 上游 | 是否把 ANALYSIS 当 FEATURE 当前 MVP；是否误入其他阶段 |
| 路径 / 范围 | 是否猜造系统路径、覆盖现有文档、改了授权外文件或段落 |
| 授权 / 停止 | 是否重复索要已给授权；是否在未决语义冲突、缺 FEATURE 或缺目标路径时继续写 |
| 推进 | 默认段落是否越界；F 是否覆盖已确认前文；明确重开或批量授权是否被无故拒绝 |
| 内容 / 受众 | 是否改变业务条件、编造承诺、让技术实现词替代产品需求 |
| 验证 / 证据 | 是否未运行即报通过、把结构校验当产品验收、漏存 diff 或退出码 |

## 输出

每条发现写清：**用例与断言 ID、真实行为与证据、根因或待核实假设、最小修改位置、预期效果、回归用例**。

P0 先处理越权写入、错误上游/落点、语义越界和虚假完成；P1 报告可读性及其他质量缺口。发现证据不足，说明补什么证据，不编造根因。不以出现某个词或固定流程口号作为修复目标，也不因一次失败叠加无关的通用门禁。

修复后在新临时工作区重跑失败用例及相邻边界，如“局部改写 / 只读评审”“默认 F / 明确重开”“FEATURE 已有 / FEATURE 缺失”。保留修复前后记录，运行方法见 [evaluation.md](../references/evaluation.md)。
