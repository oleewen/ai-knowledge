# 设计原则（sdx-prd）

PRD 回答角色如何完成任务、成功如何被验证。章节结构与逐章通过标准以 [prd-template.md](../assets/prd-template.md) 为准。

## 写作取舍

| 原则 | 执行方式 |
| --- | --- |
| 当前 MVP | 以 FEATURE 的阶段范围与优先级为依据；后续能力只在范围说明中列出 |
| 证据优先 | 故事、流程与规则沿 [追溯关系](core-concepts.md#追溯关系) 引用；冲突、缺失标待澄清，不补造事实 |
| 业务表达 | 写角色能力、输入输出与可观察结果；接口、DDL、选型交给 ASD/DSD |
| 按需加载 | 从目标索引进入，只读本段相关 FEATURE、背景和 knowledge |
| 模板稳定 | 保留十一章及必需小节；不适用说明理由，未完成标待补充 |
| 可测验收 | §9 给指标与度量，§10 对应故事和指标；未知阈值待确认，不能用“快、稳定”等词替代 |

## 场景细化

- 流程节点简述动作并标 BR；规则正文集中 §7。跨系统交互说明业务边界、同步/异步、关键输入输出及回调。
- UC 使用业务角色，列前后置与扩展场景；UC 与 US 双向引用。
- US 具备独立演示价值，含正常和边界/异常 GWT；强依赖时提出拆并建议后确认。
- 数据字典说明业务字段类型、必填、枚举与含义；状态定义含终态与非法转换策略，不写数据库表结构。
- BR 互斥时说明优先级与化解策略；不能通过换编号掩盖冲突。

阻塞与误用处理见 [反模式](anti-patterns.md)；交付检查见 [quality-checklist.md](quality-checklist.md)。
