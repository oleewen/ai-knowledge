## 基线与修复依据

改前 skill-creator 校验报 `Description cannot contain angle brackets (< or >)`；原描述中的简写分隔符已移到正文。旧评测模板与现行确认协议不一致，且只用断言 ID 作证据，无法区分未测与通过。

改前另做两例临时执行：单文件禁止搜索时未写入；主文件已授权、关联只读时仅修改主文件。未观察到这两例违反原技能，不能据此声称原技能存在稳定行为缺陷。

首轮扩展评测暴露三个实际失败：

| 用例 | 观察到的失败 | 修正与复测 |
| --- | --- | --- |
| revise-trigger-002 | 禁止全库搜索，仍执行 `rg --files` 枚举工作区 | 将首次读取规则放在入口；单例只读目标文件及必要契约 |
| revise-authorized-batch-001 | 已确认两文件且禁止额外检索，仍枚举出 unrelated.md | 直接读已确认路径；单例完成两文件修订，无额外枚举 |
| revise-discovery-only-001 | 全目录术语检索命中二层正文；先读关联再改主文件 | 关键词限主文件与一层候选；单例先改主文件，再只读关联 |

中间一次清单驱动的分组复测仍出现启动枚举偏差，未计作成功。随后将单例请求和前序确认直接交给全新执行上下文，三例均通过。入口修正与测试启动方式同时变化，不能单独归因于措辞修改。

评测保留入站路径检索与术语检索的区别：允许用主文件路径查直接入站引用；一层许可不授权对更深正文做术语扫描。首次失败的全目录术语扫描仍判失败。

代码评审还复现了重复 JSON 键覆盖失败状态的问题。先补回归并观察失败，再统一采用拒绝重复键的解析器，三个重复键子场景均通过。另补了“重复精简后回到烤干”的正向断言，防止空操作被误判为通过。

后续审查发现受众改写断言只检查时限承诺，保留 `worker`、`settlement` 的正文也可能通过。评测集 4.0.1 已要求最终正文实际改为业务语言，并补充正负样例。独立评审者在隐藏预期标签后判分：负例仅受众改写项失败，正例三项通过，均符合预期，见 [校准记录](audience-grading-results.json)。按强化后的断言复核原有实际产物“退款将在三个工作日内到账。”仍通过；未重跑任务或改写首轮历史结果。

继续审查发现一层关联用例缺少操作顺序判据：先读关联再正确修改主文件，仍可能通过原断言。评测集 4.0.2 将“先改主文件，再查关联”纳入 `bounded-discovery`，并用最终文件相同、动作顺序不同的两个样例校准。修复复审进一步将顺序限制收窄到关联检索，明确允许修改前在主文件内定位正文；两个样例均含此定位步骤。最终独立盲评拒绝顺序错误的负例，通过正例，见 [顺序校准记录](discovery-grading-results.json)。既有单例记录也符合新要求：`actions[5]` 修改主文件，`actions[6]` 才读取关联。保留 20 场景、52 断言及首轮历史记录，本次未新增真实任务执行。

## 覆盖与限制

- 覆盖触发/分流、授权复用与扩批、同词异义、引文/代码/锚点保护、短词和同名歧义、缺证事实、knowledge 引用、hunk 精简及写后停顿。
- 首轮由两名独立执行者各处理 10 例，属于分组冒烟检查；三个关键边界再各用全新上下文单独执行。17 个未失败场景未在最后一次入口微调后全量重跑。
- 原始输入与预期断言分离；执行者未见答案，评审者独立比较实际文件与 fixture。最终三个单例也逐文件核对，范围外 fixture 未变。
- 工具行为依据执行者保存的命令记录；没有独立捕获全部底层工具日志。文件内容证据经过独立比较，响应证据保留具体原句。
- 路由用例只验证选择正确流程，没有执行下游技能。每场景仅有限次观察，不代表统计成功率或所有仓库均适用。
- 系统默认 Bash 3.2 无法启动仓库检查；改用已安装的 Bash 5 后相关回归通过。评分器仅依赖 Python 3 标准库。
