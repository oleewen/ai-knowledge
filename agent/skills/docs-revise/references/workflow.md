# docs-revise 工作流

先按 [gates.md](gates.md) 确定单元；写前采用 [意图澄清](../../../references/intent-clarify.md)，写后采用 [单元推进](../../../references/unit-cycle-protocol.md) 与 [烤干](../../../references/grilling-skill.md)。

## 1. 读取与收口

范围明确时，直接读取清单内路径及适用的仓库契约；仅路径不明时才定位候选。确定改动摘要、语义边界、关联策略和起始单元，直接使用用户已给出的参数。

按 [范围模板](../assets/docs-revise-scope-ack-template.md) 输出公共六项，标明「当前阶段：意图澄清」。单点修复可用一屏摘要。未获写前确认不写入；已有确认见 gates。

## 2. 定向修改

只修改确认的单元；先核对上下文，再应用替换或纠错。保留原读者口吻及任务无关结构，写作遵循 [精简原则](../../../references/simplify-principles.md)。

涉及路径或标题时检查受影响引用。若修复需要扩大清单，先报告候选和影响，再确认；不要为了清除旧词而改历史引文、代码协议或异义用法。

## 3. 验证与烤干

| 对象 | 写后默认 |
| --- | --- |
| 主文件、关联批次、回链修复批次 | 必须烤干 |

按 [质量清单](quality-checklist.md) 查实际改动。烤干中修订后，依共享推进协议做本轮 hunk 的 simplify 遍，再回烤干；次数、豁免和空 diff 处理均以共享协议为准。

## 4. 候选与下一批

在已获准的检索范围内，按 [引用链](related-doc-discovery.md) 和 [关键词](semantic-keyword-discovery.md) 发现候选。记录路径、同概念证据、建议改动或保留理由。

标明「当前阶段：烤干」，报告本单元已改文件、验证结果、剩余候选与覆盖限制。收敛后停等共享协议的用户动作；获准推进后，下一批重新走意图澄清。整篇重组或 SSOT 去重需求转 docs-simplify。
