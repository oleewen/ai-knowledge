# sdx-test 操作层陷阱

概念反模式：[references/anti-patterns.md](references/anti-patterns.md)。

## 参数向导

- 支持逐项确认与快捷组合。
- 禁止退回已删除的 HTML gate / `PENDING→CONFIRMED` / 会话 spec 写前主线；主线=参数向导 + 「澄清 → 生成 → 烤干」（见 [unit-cycle-protocol.md](../../references/unit-cycle-protocol.md)）。
- `IDEA-ID`、`N` 须与 `PRD-{IDEA-ID}-{N}.md`、`DSD-{IDEA-ID}-{N}.md` 同链。
- 缺 `DSD` 时可收窄范围继续，但必须显式记录技术基线盲区，不能假装“全覆盖接口”。

## 推进环（澄清 → 生成 → 烤干）

协议正文见 [unit-cycle-protocol.md](../../references/unit-cycle-protocol.md) 与 [intent-clarify.md](../../references/intent-clarify.md)（sdx 无 `S`）。本文件只补技能特有陷阱。

- 一次只处理一个当前段；可细到单个用例组、单个接口异常组、单个回归范围块或单个进出标准块。
- 当前段若有 `>=2` 条真实测试策略路径，先在当前段内完成方案比选。

## 内容边界

- `§1` 写测试目标、范围、策略，不要把大量具体用例表提前塞入。
- `§2` 承接主要用例设计，按功能、接口、业务规则、异常、性能、回归分组。
- `§3-§4` 写数据与环境，不要偷写自动化实现说明。
- `§5` 的进入/退出标准必须可检查、可度量，避免“测试完成”空话。
- `§6` 写附录、自查与补充，不要把正文迁移到附录。

## 测试质量

- 每组用例至少锚定 `US/BR/API/影响面` 之一；缺证据时要显式标注待澄清。
- 接口异常组优先覆盖参数、权限、幂等、并发和依赖异常。
- 回归范围按“核心流程 → 直接影响 → 间接影响”排序，不要无序罗列模块。
- 数据准备要写边界值、异常值、特殊字符、空值或极值策略。
