## 门禁状态机

```
[阶段一：参数确认]
    ↓ 全部参数确认（或 S/F 跳过）
[阶段二：逐门禁交互]
    全量 6G：G1 → G2 → G3 → G4 → G5 → G6
    精简 4G：G(1–2) → G3 → G4 → G(5–6)
    每门禁：草案呈现 → （可选）多方案对比 → 确认点逐一确认 → 门禁收口
    ↓ 全部门禁收口（或 S/F 跳过）
[Qclose-1 总确认]
    ↓ C / S（PENDING → CONFIRMED）
[阶段三：文档生成]
    骨架 → chunk 1–6（或精简 4 chunk）→ 终检
```

## 回跳影响面评估

用户回跳到 G{k} 并修改结论后，评估后续门禁的依赖类型：

| 依赖类型 | 判断标准 | 处理方式 |
|---------|---------|---------|
| 强依赖 | 后续门禁与 G{k} 新结论显式矛盾，或引用同一实体（同一 US/TC、同一回归范围） | 须重新确认 |
| 弱依赖 | 后续门禁大量引用 G{k} 的术语、范围、优先级或验收表述 | 建议重新确认 |
| 无依赖 | 后续门禁内容与 G{k} 无关联 | 保持已确认状态 |

**典型示例**：回跳 G2 增删用例或改优先级 → G3 数据需求、G5 退出标准往往为强依赖；回跳 G1 改测试范围 → G2–G5 多需至少弱依赖重审。向用户说明影响面后，由用户选择「仅强依赖重走」或「强弱一并重走」。

## 待澄清项（Q-n）协议

**触发**：阶段二任意门禁中出现歧义、矛盾或信息缺失时，立即标注 Q-n。

**格式**：

```
Q-{n}：{问题描述}

背景：{为什么需要澄清，影响哪个决策}

选项：
1. {具体含义描述}（推荐）
2. {具体含义描述}
3. 其他（请说明）

请选择：C / M / S / F
```

**规则**：
- 每次只提一个 Q-n，等用户回答后再提下一题
- 选项描述具体含义，不写「方案A/方案B」等抽象标签
- 澄清结论写入对应门禁草案，不单独设「待澄清问题」章
- 用户选 S 时，在 spec 中标注「Q-{n} 待澄清」并说明影响范围
- **Q-n 优先模式**（可选）：多条 Q-n 积压时，可在全部门禁草案完成后集中确认，再进入 Qclose-1

## G{n} 填充要点

### G1：§1 概述

1. **输入**：加载 PRD，提取 US-n、验收标准、BR-n、NFR；**DSD**/`specs` 存在时提取 API 规约、架构/实现影响面（可兼读 **ASD**）。
2. **§1.1 测试目标**：引用 PRD、**DSD/ASD** 路径或 ID，MVP-Phase-{N} 与参数一致。
3. **§1.2 测试范围**：新增/变更/回归范围与当前 MVP 对齐；回归范围对齐 **DSD**/ASD 影响面（如有）。
4. **§1.3 测试策略**：单元/集成/E2E（或项目约定层次）与覆盖目标；与 §5 进出标准可互证。

**depth**：`quick` 压缩策略叙述；`standard` 完整；`deep` 强调性能/并发/安全相关策略（若 NFR 有要求）。

### G2：§2 测试用例

1. **§2.1 功能**：US-n Given-When-Then；TC-{NNN} 与优先级。
2. **§2.2 接口**：**DSD §2**/规约 YAML 中 API 正常/参数/权限/幂等/并发；TC-API-*。
3. **§2.3 业务规则**：BR-n 等价类与边界；TC-BR-*。
4. **§2.4 异常**：系统/数据/并发/依赖；TC-EX-*。
5. **§2.5 性能**：`deep` 或 NFR 要求时充实；否则标「不适用」及原因。
6. **§2.6 回归**：与 §1.2 回归范围一致；TC-REG-*，说清防什么回归。

**depth 影响**：

| depth | 行为 |
|-------|------|
| quick | 仅 P0 功能与核心接口；从简异常/回归 |
| standard | 完整六类用例 |
| deep | 增加性能与安全、详细并发 |

### G3：§3 测试数据

枚举数据类型、数量、关联；准备方式（脚本/手工/脱敏）；边界值与特殊数据（空值、超长、特殊字符）；外部依赖 Mock/Stub 策略。

### G4：§4 测试环境

服务/库/中间件/外部依赖版本与 **DSD**/部署说明一致或说明差异；Mock/Stub 策略可执行。

### G5：§5 测试进出标准

- **进入**：代码、单测、环境、数据就绪等可检查项
- **退出**：通过率（如「P0/P1 用例通过率 100%」）、缺陷等级、覆盖、性能（如适用）可度量
- **回归执行顺序**：核心流程 → 直接影响 → 间接影响

### G6：§6 附录与定稿整合

§6.1 变更历史；§6.2 质量自查表逐项判定（`- [ ]` / `- [x]`）；文末 fenced yaml，**禁止**文件头 `---` frontmatter。
