# TDD 内容原则

保留 [模板](../assets/tdd-template.md) 六章及固定小节；不适用说明原因，未解决标待澄清。生成遵循 [精简原则](../../../references/simplify-principles.md)，逐项验收以模板 §6.2 为准。

## 用例与追溯

- 先读 PRD 与变更影响面，再按当前用例类型读取 DSD/ASD 的相关契约；不通读 knowledge 全树。
- 用例应能复现：前提、输入/触发、步骤或动作、可判断的预期结果、优先级与来源。简表缺少的条件在同组说明中补齐。
- 功能用例对齐 US/FR；规则对齐 BR；接口对齐真实 API 及错误码、幂等；异常与回归指向设计风险或变更影响面。引用不等于已证实覆盖，需核对实际断言。
- 正常、关键异常与边界按风险覆盖；接口组评估参数、权限、幂等、并发及依赖异常。不把无证据的响应码或阈值写成预期结果。
- 回归按核心流程、直接影响、间接影响说明验证顺序与原因；与 §1.2 范围一致。
- 数据说明边界/异常值、规模、来源与脱敏；环境说明版本、依赖、Mock 行为及与设计的差异。进出标准须可检查并与策略互证。

## 覆盖目标

以下为本技能原有的**可调整规划默认值**，不是所有项目的验收硬门槛，也不是实测结果：

| 层次 | 默认目标 |
| --- | --- |
| 单元 | 行覆盖率 ≥80% |
| 集成 | 接口覆盖率 100% |
| 端到端 | 核心场景覆盖率 100% |

在 §1.3 明确适用层次、统计分母、排除项及目标来源；优先沿用项目已有要求，调整须同步 §5。没有执行证据时只记目标，不写“已达标”。

## 内容边界

TDD 写“测什么、如何判断”，不复制完整 OpenAPI、DDL 或上游故事，不生成自动化实现。缺基线按 [workflow.md](workflow.md#输入与缺口) 处理；测试预期与上游矛盾时先澄清，不借测试设计暗改产品或接口语义。
