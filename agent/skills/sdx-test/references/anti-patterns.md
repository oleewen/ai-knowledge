# sdx-test 反模式

| 误用 | 处理 |
| --- | --- |
| 将测试驱动开发或 Jest/pytest 编码识别为 TDD 文档写作 | 按用户的实现任务处理，不启动本技能向导 |
| 纯校验先问写作参数或修改文件 | 直接运行只读校验并报告结果 |
| 无 PRD 仍编造测试预期 | 按 [输入与缺口](workflow.md#输入与缺口) 停止生成；缺 DSD 的受限继续不能套用于缺 PRD |
| 缺 DSD 却承诺接口全覆盖 | 收窄到 PRD 已支持范围，记录技术盲区 |
| 把 `F` 当覆盖前文的整篇重写 | 按 [gates.md](gates.md) 补齐剩余；全文修订须重新界定范围 |
| 在 TDD 中重写 API/DDL 或输出执行报告 | 追溯设计契约；区分测试设计与测试执行 |
| 统计 TC 数量就认定覆盖达标 | 对照需求、接口、规则与影响面核查映射及预期结果 |
| 将默认目标或结构校验通过写成实测结果 | 保留目标/设计状态，不伪造已执行或已通过 |
| 要求旧 HTML gate、CONFIRMED 文件或写前 hook | 使用 [共享推进协议](../../../references/unit-cycle-protocol.md)，不恢复已移除机制 |
