# sdx-feature 反模式

| 误用 | 正确落点 |
| --- | --- |
| 仅因提到「需求分析」就写 FEATURE | 按目标产物分流；ANALYSIS 用 sdx-analysis，PRD 用 sdx-prd |
| 把零散共识材料当成已确认的 ANALYSIS | 核实同库上游，见 [输入停点](gates.md#输入停点) |
| 以 F 跳过概览确认或覆盖已确认前文 | 按 [概览门禁](gates.md#2-概览门禁) 和共享 F 语义执行；额外授权须有明确依据 |
| 重复询问已知参数，强制用户重走默认流程 | 沿用已有参数及授权，只解决未决项 |
| 用里程碑序号决定优先级，或机械生成同数量 MVP | 按目标关键性与交付价值判断，见 [核心概念](core-concepts.md) |
| 靠脚本退出 0 声称已获共识或已通过业务评审 | 报告检查范围；语义、流程与结构分别举证 |
| 给终稿自查表全部打勾以表示“写完” | 对照 [质量清单](quality-checklist.md)，未验证项保留未勾选 |

不恢复已移除的 HTML gate、CONFIRMED、会话 spec 或写前 hook；这些都不是当前技能的执行前提。
