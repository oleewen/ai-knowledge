# sdx-feature 推进协议（binding）

共享流程只在 [意图澄清](../../../references/intent-clarify.md)、[单元推进](../../../references/unit-cycle-protocol.md)、[烤干](../../../references/grilling-skill.md) 维护。本文件补充 FEATURE 的对象、停点和语义边界；执行步骤见 [workflow.md](workflow.md)。

## 对象定义

当前段为六章 FEATURE 中的章节或小节；§2 先独立处理 `### 概览`，之后可细到单个 FR。默认动作 `C/M/G/F`，无 `S`。

沿用用户已明确的参数和本轮授权。用户明确要求改变默认推进方式（如本轮一次写完整稿）时，按其指定范围执行，不为重复确认强制插入默认菜单；缺失事实仍标未核实。单独选择 `F` 仅具有共享协议中的批量补齐含义，不自动授权覆盖已确认前文。

## 技能追加澄清字段

- 同库上游 `ANALYSIS-{IDEA-ID}.md`、共识依据及对齐章节。
- §6.1 里程碑及覆盖范围是否足以拆能力。
- `depth` 与本轮范围；§2 是否已确认概览、当前是否为单个 FR。

## 输入停点

| 情况 | 处理 |
| --- | --- |
| 缺同库已共识 ANALYSIS | 转 `sdx-analysis`；会议纪要或等价材料不能默认为已完成的 ANALYSIS |
| §6.1 里程碑空或过粗 | 停止拆 FR；回补 ANALYSIS，或由用户提供已确认的等价里程碑清单并注明依据。该清单不替代 ANALYSIS 本身 |
| 其他上游内容不全 | 列出缺口与影响；不可推导的结论标待确认，不伪造覆盖 |
| 公司 / 解决方案库 | 分流 `sdx-domains` / `sdx-solution`，不创建本层 `features/` |
| 无模板或输出路径不可确定 | 保留现有内容，先解决路径或资源缺口 |

## §2 概览门禁

在默认分段流程中，概览须完成写后 `C` 才展开 FR 正文。概览处选择 `F`，仅批确认并生成概览本身，不能顺带写后续 FR。

概览与 FR 的字段、拆分、长度、模块和里程碑规则集中于 [core-concepts.md](core-concepts.md#概览与-fr)。当前 FR 只可对齐对应概览行；改变已确认范围、模块或能力拆分时，按共享协议先确认前文回改。§2 整章收口必须核对概览和正文。

## 语义问题清单（烤干须停）

以下问题若超出已有授权，先给结论、推荐和数字选项，确认后修订：

- 目标、范围、承诺、优先级、术语或风险发生变化。
- FR 清单、模块归属、关联目标、里程碑或正文职责冲突。
- MVP 装载遗漏/重复、无独立交付价值、依赖成环，或数量偏离里程碑而无解释。
- 后文要求修改已确认前文；回改后重开受影响段。

纯长度压缩、标题与概览同步等若不改语义，可在当前对象内修订；若改变能力或承诺，则按上表停问。

## 技术决策推进门禁

出现持久技术/架构决策时读 [ADR 协议](../../../references/sdx-adr-protocol.md)，并遵守以下 FEATURE binding：

- 写前查本层 CONTEXT 与已有 ADR；一致则复用，冲突先确认。
- 实现向且不改变业务/集成边界时，可在已授权范围内落 ADR；改变边界则停回 `sdx-analysis`。
- 推进前，本段新决策已落 ADR、登记 CONTEXT，并在 FEATURE **§6.2** 链接；不残留 `ADR-待定`。没有技术决策时不创建空台账或空引用。

脚本通过不代替上述语义检查，也不证明用户已确认。
