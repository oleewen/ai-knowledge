# DSD 内容契约

结构由 [dsd-template.md](../assets/dsd-template.md) 定义；写作遵循 [精简原则](../../../references/simplify-principles.md)。本文件只补 DSD 的内容与追溯要求。

## 章节职责

| 章节 | 内容 |
| --- | --- |
| §1 设计概述 | 目标、约束、关键决策。与 ASD §1 保持可追溯一致；仅有 spec-asd 时依其 §1–§2 与 `refs`，摘要须说明差异 |
| §2 详细设计 | 应用架构、API、业务逻辑、数据访问、非功能；全部实现级契约及其追溯在此维护 |
| §3 附录 | 变更历史、自查与必要补充，不承接移出的实现正文 |

保留固定章节；不适用写原因，未解决写待澄清。DSD 不要求另建 `specs/{service}/` 或独立详设 Markdown。图、示例、伪代码按当前设计需要使用，不将模板示例当作已选架构。

## 实现级条目

| 对象 | 至少说明 |
| --- | --- |
| API | 签名、请求/响应、校验约束、错误码与触发条件、幂等或无需幂等的理由、异常处理 |
| LOGIC | 业务规则、状态/时序、事务边界、一致性与失败恢复；图和伪代码表达必要设计，不铺源码调用细节 |
| TBL/DDL | 主键、字段/约束、审计字段、查询与索引依据；有缓存则明确失效与一致性 |
| 非功能 | 与上游相符的安全、性能、可观测约束；未确认指标标待澄清，不写泛化承诺 |
| DD | 选项、结果、理由及影响；只比较真实可行路径，不扩大 MVP |

## 编号与证据

保留已有 ID；新增依现有序列分配 `DD-{NNN}`、`API-{NNN}`、`LOGIC-{NNN}`、`TBL-{NNN}`，核对重复、引用与编号连续性，历史空号说明原因。

- 在条目附近指回 PRD 的 US/FR 与 ASD §3 对应行，或 spec-asd 对应条目；不只在文首列文件名。
- 设计决策对齐需求，接口对齐用例，表变更对齐 FR，非功能对齐已确认需求。
- knowledge 实体用实际 ID；文档给文件与章节；代码给可核实位置。只读相关证据，不全树加载。
- 事实、方案与未知分开表达。技术或架构冲突按 [gates.md](gates.md) 处理，不靠 DD 编号把未确认选择写成定论。
