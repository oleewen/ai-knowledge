# 中央规约只读消费

应用设计直接读取已确认的中央 ASD/spec-asd，DSD 只写当前应用库。本文是来源定位、内容基线与 HTTP 引用的唯一约定；不复制规约、不修改中央仓、不自动 clone/fetch、切分支、暂存、commit 或 push。

## 定位与确认

1. **明确来源优先**：使用用户指定的真实文件或中央目录。允许对 `spec-asd-*.md` 的文件名做包含词或通配符匹配，不做语义近似猜测；未指定目录时才进入下一步。
2. **登记关系兜底**：从当前应用 `knowledge-links.yaml` 的 `type: parent` 解析本机 `path` 与 `dir`，只检索该 parent 文档根；路径展开遵循 [工作区路径契约](../../../knowledge/knowledge-governance.md)。登记或目录不可用时停问，不扫描全工作区、猜目录或自动获取仓库。
3. **收口候选**：明确目录内零命中时报告并停问，不静默转搜其他库；多命中列出路径、IDEA-ID、MVP 与应用供用户选择，不按修改时间、最长名称或第一条结果代选。唯一命中也须读取正文，核对 IDEA-ID、MVP 与应用归属，再沿用或取得来源共识。
4. **范围边界**：不跟随符号链接扩展到获准检索根以外。模糊词只作为匹配数据，不拼入 `eval` 或未经引用的 shell 命令。显式 ASD 路径仍可使用；已有本地规约可作为输入，但本流程不创建下发副本。

## 确认内容基线

开始设计时，对每份已确认源文件的原始字节计算 SHA-256；记录确认时间、规约 ID、HTTP 文件链接、摘要及链接一致性状态到 DSD §1.1。文件路径用于本次读取，不以本机绝对路径充当持久引用。

- 工作树可以含未提交内容，不要求用户为此先提交。
- 写当前段前及该段/全篇验收时，重新核对源摘要；变化或文件不可读即暂停受影响设计，说明差异并重新确认。更新基线前按 [gates.md](gates.md) 重开相关段落，不静默接受新内容。
- 每份源单独记录。HTTP 链接不能替代摘要，摘要也不能证明内容已发布或共识已成立。

## Git HTTP 文件链接

`architecture_ref` 指向本轮主架构源的 Git HTTP(S) 文件链接；多份来源在 §1.1 分别记录。

- 优先复用用户提供并核对文件身份的链接；否则由已核实的仓库地址、ref 和仓内路径生成宿主支持的文件浏览链接。路径段按 URL 规则编码；未知宿主或 ref 不明时请求准确链接，不猜 `main`，不套用 knowledge 实体的固定 ref 协议。
- 链接负责定位，可以指向不同于已确认工作树的远端内容。记录三种状态之一：**一致**（有实际内容比对证据）、**存在差异**（列明差异）、**未核实**（尚未核对内容或可达性）。仅生成 URL、知道本地 HEAD、或结构校验通过都不能标“一致”。
- 已知未发布内容或未推送提交时注明事实；远端是否存在尚未核实时注明“未核实”。无法构造真实文件定位链接时停问，不能用虚构 URL 完成来源记录。
- `architecture_ref` 保存裸 URL，可带 query/fragment；章节追溯在正文展开。校验器仅从 URL 文件路径检查同链 ID，不访问网络，也不验证链接内容与摘要一致。

历史 DSD 的 ID/本地路径引用保持兼容；本轮新增或修改的中央来源按本文记录。受限草稿仍遵守 [输入缺口](workflow.md#输入与缺口)，不得用来源缺失冒充已完成的基线确认。
