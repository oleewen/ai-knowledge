# 受众与语言（sdx-analysis）

> 公共维与烤干门禁：[audience-and-language.md](../../../references/audience-and-language.md)

## 主读者

**产品、需求分析**及参与范围评审的业务方。表述重点：谁能做什么、规则与验收、与谁协作。

## 宜写 / 宜弱化

| 宜写 | 宜弱化 |
| --- | --- |
| 角色、场景、主流程 | 类/接口/方法 |
| 业务规则与边界 | 表/字段、中间件 |
| 验收、优先级、所属里程碑（§4 再落入 `MVP{n}`） | 技术栈、部署形态 |
| 概览需求概要（一句话能力，≤60 字；落在所属模块职责内） | 把 BR/验收/`MVP{n}` 塞进概览表；名称/概要超长或越权 |
| 概览「所属模块」（业务能力域短名；一 FR 一模块） | 工程模块/包/服务名、协议类型 |
| 协作依赖（团队/环节） | 把跨模块职责塞进单 FR |

## 反例

| 避免 | 推荐 |
| --- | --- |
| 调用某 Service 方法 | 用户提交后进入审核 |
| 直接写表名/字段名 | 用业务对象与可查可溯表述 |
| 把实现方案写进 FR | FR 写能力与验收；技术线索进允许区 |

## 特殊允许区

技术线索收敛在 **§6.3** 并标「待研发确认」。非功能（§3）量化写「与研发共拟」。可查 `knowledge/`、index；写入须转写为场景、规则、验收、协作。

与 sdx-solution 对照：solution 偏目标/影响/思路/`M{n}` 里程碑骨架；analysis 偏概览拆 FR（挂所属模块 + `M{n}`）、BR、验收；§4 交付计划再落入 `MVP{n}`（不与里程碑硬对齐）。
