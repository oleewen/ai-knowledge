# 受众与语言（sdx-analysis）

主读者为业务与产品。按 [共享受众契约](../../../references/audience-and-language.md) 检查 A/B/C/E；正文说明谁做什么、规则和验收怎样变化。

## 表达边界

§1–§6、§7.1–§7.2 保留业务角色、场景、规则、范围、协作、成功标准与交付承诺。类、方法、表字段、中间件等实现线索移至 §7.3，并标「待研发确认」。技术决策的正式记录仍按 [gates.md](gates.md) 落 ADR。

业务化改写不得削弱原始要求，尤其是数字、单位、分位口径、时限和例外。术语可解释，已确认指标不能改成「体验达标」。

| 原始表述 | 业务表述 |
| --- | --- |
| 调用 `FeeAppealService.create()` | 提交申诉后进入审核流程（流程须有来源） |
| 写 `appeal_record` | 保存申诉记录 |
| Kafka 异步通知下游 | 将处理结果通知协作方；具体时效沿用已确认要求 |
| P99 < 200ms | 第 99 百分位响应耗时低于 200 毫秒；保留已给统计口径，缺失的另标待确认 |

若改写会新增流程、可追溯性或时效承诺，先澄清，不能借润色补造事实。
