# sdx-analysis 核心概念

## IDEA-ID

用户或已有文档提供的 ID 保持不变；新建议采用 `{YYMMDD}-{主题}`，主题用 2–6 字中文短名，例如 `261022-审批提效`。ASCII slug 保留，并在标题注明中文主题。

产物名为 `ANALYSIS-{IDEA-ID}.md`；frontmatter `id` 与文件名去掉 `.md` 后一致。下游 FEATURE 沿用同一 IDEA-ID，不因格式偏好重命名已有引用。

## 编号

| 编号 | 定义位置与含义 |
| --- | --- |
| G-n | §1.3 业务目标 |
| C-n | §3.4 业务冲突 |
| R-n | §5.1 风险 |
| Q-n | §5.2 业务问题决策，区分待确认/已决策 |
| M{n}（短名） | §6.1 关键里程碑，覆盖范围须能落到业务能力 |
| ADR-n | 技术/架构决策，落盘与登记见 [gates.md](gates.md) |

同类编号连续；跳号说明原因，修改时保留已有稳定引用。ANALYSIS 提供里程碑范围骨架；FEATURE 概览抄 `M{n}（短名）`，FEATURE §4 再划 `MVP{n}` 并挂 FR。MVP 与里程碑不硬对齐，数量差异明显时说明理由；ANALYSIS 不列 MVP/FR 清单。

## `--depth`

这是写作深度参数，不是校验脚本选项。

| 值 | 粒度 |
| --- | --- |
| quick | 压缩影响分析的叙述，保留相关高影响项及全部章骨架 |
| standard | 默认七章完整粒度 |
| deep | 加强数据影响、约束、冲突与风险，仍用业务语言 |

## ANALYSIS 七章

标题、表头与元数据字段以 [模板](../assets/analysis-template.md) 为准；验收见 [质量清单](quality-checklist.md)。深度不改变固定结构，用户限定的局部任务不扩大为全篇生成。
