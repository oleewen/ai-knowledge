## 代码问题的复现与修复方向

1. **包装器清理：** executor 使用普通 Bash 包装器调用适配器，并在 Python 返回后处理退出码，因此 Bash 保持为进程组长。外层 1.5 秒超时后 runner 返回 exit 2，但 fake Codex 与其普通子进程仍存活，manifest 为 `timeout_owner=adapter`。修复受管组身份的传递，补直接启动与包装启动的超时、中断回归。
2. **相对 executable：** 使用现有 fake CLI，传 `--codex-bin ./fake-codex`；版本字段成功写入，实际模型调用为零并报文件不存在。切换 cwd 前解析可执行路径，版本探测与实际调用共用绝对路径；纯命令名继续支持 PATH 查找。
3. **版本探测：** 让查询包装器创建普通 sleep 子进程。适配器约 10.08 秒后返回 exit 2，子进程仍为 PPID 1、状态 S。将此分支纳入进程组生命周期管理。
4. **循环软链：** 两种资源路径分别指向自循环软链，均可复现 exit 1 加 traceback。将路径解析错误转为 EvalError。此项是低频非法输入问题，列为 P3。

以上均使用本地替身，复现进程已清理。现有测试只覆盖直接启动及绝对 CLI 路径，没有覆盖上述包装与路径分支。
