# sdx-domains 评测失败分析

输入：本例原始请求、技能版本、夹具、执行轨迹、文件差异与 grader 结论。口径见 [evaluation.md](../references/evaluation.md)。

## 分析

先区分证据缺失、夹具失效与真实行为失败。按实际失败选类：

| 类型 | 观察重点 |
| --- | --- |
| 触发误判 | 公司域架构漏触发；方案、需求或 docs-* 误触发 |
| 层级/路径越界 | 非 company 写入；忽略 DOC_DIR；生成其他阶段产物 |
| 事实失真 | 未读来源；捏造 ID；混淆 BSD 层级或 CAP/VC 关系 |
| 产物错误 | 总图关联失实；分域缺支撑链；PL 扩写定义；历史文件被重命名 |
| 授权/推进错误 | 写入未确认语义；越过当前段；F 覆盖前文；拒绝合理重开 |
| 证据不足 | 仅复述协议，未提供实际文件/工具证据；旧结果冒充新结果 |

## 输出

每个发现只写四项：

1. **失败与证据**：用例 ID、断言 ID、可定位的轨迹或差异；缺证据就标未核实。
2. **根因**：区分技能指引、执行偏差、夹具或评分问题，勿从单次失败直接推广成通用门禁。
3. **最小修复**：目标文件/段、所需修改及理由；越界写入与事实失真优先。
4. **回归案例**：给能复现的原始请求和最少材料，并加一个相邻合法场景，避免修复后过度拒绝。

先复测受影响案例；是否扩大测试范围取决于改动影响。真实新证据才可更新结论，不能把静态审查写成运行通过。
