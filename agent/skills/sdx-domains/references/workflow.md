# sdx-domains 工作流

先确定公司文档根和当前段，再按 [gates.md](gates.md) 推进。总图与分域模板见下表，不套用解决方案七章。

## 1. 定位输入

- 从目标工程 `.docsconfig` 读取 `KNOWLEDGE_TYPE`、`DOC_DIR`，不执行配置内 shell。仅 `company` 可进入写作；缺配置、层级不符或文档根不明时，报告实际值并停止写入，不改配置绕过校验。
- `{DOC_DIR}` 可为任意已配置目录；`company/` 只是元库示例。不要用环境变量将 `meta` 仓伪装成公司库。
- 从目标库索引按需定位当前段涉及的 VC、BD、BSD-L1、CAP；下层 PL 从已有映射或可核实材料取纯 ID。关系含义见 [core-concepts.md](core-concepts.md)，不全树加载知识正文。
- 确定总图或分域、目标路径、起始映射块或章节。单域需已有 `BD-ID`；已有文档先核对其文件名、frontmatter 和总图引用，不自动改名。

用户已给出的参数沿用。只补当前段缺口；缺少后续 PL 信息不阻塞已核实的价值链段。

## 2. 选定当前段

| 任务 | 当前段 | 模板 |
| --- | --- | --- |
| 总图 | 一组已确认的 VC/BD/分域映射 | [domain-map-template.md](../assets/domain-map-template.md) |
| 单域 | 价值链、BSD-L1 支撑、范围或 PL 中的一节 | [domain-template.md](../assets/domain-template.md) |

写前按共享六项清单确认本段目标、边界和路径。新文件的骨架也纳入本轮授权；已有文件按实际标题与内容定位当前段，保留旧章号。总图和分域是不同对象，不因修改其中一个而覆盖另一个。

## 3. 生成与烤干

按 [精简原则](../../../references/simplify-principles.md) 写入。只陈述已核实的关系；材料缺口标「待确认」，不补造实体、归属或链接。总图中的文档链接须指向已存在文件；尚未生成分域时，写纯 ID 并标待生成。

### 写后默认表

| 对象 | 默认烤干 | 重点 |
| --- | --- | --- |
| 总图映射块 | 必须 | VC/BD 关系、文档路径、与已确认分域的一致性 |
| 分域章节 | 必须 | BSD-L1/CAP 支撑链、范围、PL 归属与来源 |

用 [质量清单](quality-checklist.md) 检查当前段，受众要求见 [audience-and-language.md](audience-and-language.md)。跨对象不一致按 gates 停问，不能静默回写总图或其他域。

收敛后按共享协议等待用户动作。全部对象完成后检查总图与分域一致性，运行全量校验。未完成章节或待确认关系须如实报告。

## 校验脚本

在目标工程中使用 Bash 5+ 运行 `scripts/validate-domains.sh`；脚本依赖 Python 3 和同一 agent 树的 `scripts/lib/docsconfig.sh`，不单独复制脚本使用。

| 参数 | 行为 |
| --- | --- |
| 无参数 | 检查总图及全部分域文件；报告非平铺 DOMAIN 文件，拒绝无法纳入平铺检查的目录软链 |
| `--file PATH` | 检查 `domains/` 直属的指定 DOMAIN Markdown；路径相对当前工作目录或为绝对路径 |
| `--help` | 显示用法，不加载工程配置 |

脚本只读：检查层级、真实路径、首段 frontmatter、必要标量字段、正文及总图本地分域链接；成功退出 `0`，错误非零。总图不要求 `id`；分域 `id` 须匹配文件名，旧稿不要求补 `type/status`。

必填字段支持顶层单行裸标量、单引号标量及 JSON 兼容的双引号标量，不支持续行或块标量。脚本不验证完整 YAML、实体存在性、关系真伪、章节语义或业务完成度；这些仍需质量清单核对。单文件通过不代表整个目录通过。
