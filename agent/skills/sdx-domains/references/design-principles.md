# sdx-domains 设计原则

## 证据使用

从目标库索引下钻到本段实际涉及的实体。文件、用户材料与既有域文档矛盾时，展示冲突并确认，不能自行将新说法写成 knowledge 事实。

公司语义与边界以 [知识治理](../../../knowledge/knowledge-governance.md) 为准；目录以 [知识布局](../../../references/knowledge-layout.md) 为准；产物结构以本技能模板为准。发现冲突时报告，不把不同层的模板拼接成一份文档。

## 缺口处理

| 缺口 | 处理 |
| --- | --- |
| 当前段缺实体或关系证据 | 列出缺失依据，停止该段；不从原始需求生成新实体 |
| 后续段缺范围或 PL | 留待该段澄清；不阻塞无依赖的当前段 |
| `domains/` 不存在 | 在目标路径与创建范围已确认后创建 |
| 模板缺失 | 报告所需模板；不回退到 SOLUTION 七章 |

写作精简只改善表达，不改变实体、归属、范围或承诺。验收见 [quality-checklist.md](quality-checklist.md)。
