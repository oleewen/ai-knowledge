# agent-install 评测

在元库执行。用例见 [evals.json](../evals/evals.json)，评分见 [grader.md](../agents/grader.md)。结构检查、脚本回归、技能行为分别报告；前两者通过不能代替模型行为通过。

## 脚本回归

用 Bash 5+ 执行 `bash tests/run.sh`（相对本技能目录）。测试调用真实安装器，临时目录承载源、安装树和 IDE 链接；沿用 [test-lib.sh](../tests/test-lib.sh) 的隔离调用函数。`cases/17_exclude_development_resources.sh` 覆盖首次安装、升级、rsync/cp 两条路径、顶层与嵌套缓存、第三方内容及运行资源保留；`cases/18_inferred_workspace_conflict.sh` 覆盖冲突拒绝零写入、预览、显式选择和非冲突执行。

## 独立行为运行

1. 控制方按用例 `setup` 在新临时目录准备夹具；没有 setup 的旧例按 prompt 补齐必要原始文件。以真实临时绝对路径替换 `case_root` 等示例路径，保存最终投递请求。
2. 给被测代理技能运行说明、当前用户请求及必要原始文件；评测集、预期答案、评分器和未来消息由控制方保留。运行副本排除 tests、evals 和 grader。被测代理只通过绑定临时安装树的运行器调用安装器，不能触及真实全局环境。目录分离不是操作系统沙箱。
3. 控制方保存每次真实安装器调用的参数、输出和退出码，以及操作前后的配置字节、资源内容和链接目标。多轮例在首轮真实返回后保存快照，才通过同一代理的后续回合投递 `follow_up`；不能让代理模拟未来用户回复。
4. 评分方对照实际响应与产物逐断言评分。操作授权、失败停止等顺序要求检查调用日志；零写入与内容保留检查快照，不能以口头承诺替代。没有真实模型选择过程的路由用例不报告发现率。

`agent-install-failure-001` 保留给定日志的诊断场景；其 `execution_variant` 另验证真实失败后的决策。仅在临时运行器内注入复制失败，保留此前已完成的配置写入；该变体必须有真实失败调用及后续响应证据。

按本次变更和风险选择代表用例；记录技能版本或差异、模型/代理 ID、投递输入、证据位置、通过/失败/未测及原因。抽样不称全量通过，手工评审不称统计成功率；脚本或技能变化后只复测受影响场景，并说明未重跑的范围。
