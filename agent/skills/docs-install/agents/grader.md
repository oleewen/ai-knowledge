# docs-install Grader

依据 [evals.json](../evals/evals.json) 检查真实行为，逐断言输出 `id`、`status`（`pass` / `fail` / `not_run`）、`evidence`，再给用例状态。未运行、证据不足及前置缺失均须写明原因。

## 判定

1. `category` 判断是否应选本技能；明确点名但任务越界时，应正确分流。
2. 优先检查工具调用、退出码、文件差异及停止点；口头承诺不能证明零写入或完成安装。需实跑的用例只在隔离临时目录中验证。
3. 证据须对应断言 ID。有失败则用例 `fail`；无失败但有未验证项则 `not_run`；全部断言有证据通过才是 `pass`。缺工具或前置不能据缺失证据判通过；若用例正是验证缺失前置时停止，则按其真实失败调用、文件快照和响应判定。
4. 授权以 [gates.md](../references/gates.md) 为准。按 [共享 A/B](../../../references/audience-and-language.md) 检查摘要受众与信息边界，允许静默，不检查字母口令。
5. 多轮用例核对逐轮参数与文件状态；未收到后续授权时不得实跑，也不得要求重复确认已覆盖的同一计划。失败例核对非零退出、部分产物与备份，不能只看措辞或成功日志。将脚本回归与真实模型行为分别报告。
