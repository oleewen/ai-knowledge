# 文档规范

> **结论**：改 Markdown 前先判 A/B/C，再定 `frontmatter title`、可见 `# H1` 与 `MD025` 豁免。  
> **范围**：本仓文档分类与代码/注释底线；分类细则以本文为准（`CONVENTIONS` 仅摘要）。

## Markdown 文档分类

### 先判类，再写结构

新增或修改前，判为 `A 人类入口` / `B 机器规约` / `C 元数据/混合` 之一，再决定 title、H1、MD025。禁止先复制旧文件再事后补判。

| 类 | 典型 | title | 可见 H1 | 说明 |
| --- | --- | --- | --- | --- |
| A 人类入口 | `README.md`、`AGENTS.md`、`INDEX-GUIDE.md`、`index.md`、导航型 README | 仅生成链/读取约束需要时保留 | 默认保留（读者首标题） | — |
| B 机器规约 | per-entity `{ID}.md`、`SOLUTION-*`/`ANALYSIS-*`/`PRD-*`/`ASD-*`/`DSD-*`/`TDD-*`、模板/样例/规约 | 默认保留（机器消费） | 按规约 | **不得**只为消 MD025 而删 `title` |
| C 元数据/混合 | `docs-meta.md`、`knowledge-meta.md`、`INDEXING-LOG.md`、兼具阅读与规则消费的说明 | 边界未拆清前可阶段性双留 | 可双留 | 可配单行 `MD025` 豁免 |

### `MD025` 使用规则

- 同时依赖 `frontmatter title` 与可见 `# H1` → 单行 `MD025` 豁免为必要豁免。
- 已只保留一种标题机制 → 不得继续保留该豁免。
- 新文档必须先判类。

## 代码文档规范

| 对象 | 必含 |
| --- | --- |
| 公共 API（JavaDoc） | 参数、返回值、异常 |
| 类 | 用途与职责、重要设计决策、使用注意 |
| 包（`package-info.java`） | 包用途、主要组件、包级约束 |

## 注释规范

| 类型 | 要求 |
| --- | --- |
| 代码注释 | 解释复杂业务逻辑、重要算法、代码局限 |
| TODO | 写明待办、优先级、负责人（例：`TODO(high): … - @张三`） |
