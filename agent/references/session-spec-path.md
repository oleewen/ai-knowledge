# 会话材料路径契约（Agent SSOT）

> **定位**：工程根 `.superpowers/` 的统一落点、迁移与目录外引用隔离。正式产物推进见 [CONVENTIONS.md](../rules/CONVENTIONS.md#artifact-gates)；会话材料不替代正式知识或用户确认。

**最后更新**: 2026-10-29

## 统一落点

| 材料 | 工程根相对目录 | 用途 |
| --- | --- | --- |
| 工作规格 / 设计备忘 | `.superpowers/specs/` | 可选工作稿与 brainstorming 备忘 |
| 实施计划 | `.superpowers/plans/` | 计划及执行任务说明 |
| 执行证据 | `.superpowers/sdd/` | 日志、快照、diff、运行记录 |

三类材料均从目标工程根解析，与 `DOC_DIR`、知识库层级和配置是否存在无关。技能源码、安装资源及正式知识产物仍由各自契约管理。

- **工程根**：优先使用已确认的目标工程根；Git 工程可用当前 checkout 的根核对。子目录调用仍落到同一工程根；独立 worktree 使用自己的根。非 Git 工程根不明确时先确认，不猜测父目录。
- **落点校验**：写入前检查实际路径仍在目标工程内，禁止通过已有软链越界。规格、设计备忘和计划使用 Markdown；日期与阶段后缀沿用所属流程命名，不是闸门凭证。
- **版本管理**：在当前生效的 Git 全局忽略文件中配置 `.superpowers/`，覆盖各工程会话目录。忽略不影响已跟踪文件；不得自动取消跟踪。旧目录忽略规则可留作兼容。
- **扫描边界**：知识索引、可视化与正文链接扫描排除整个 `.superpowers/`，包括显式指定该目录、其子目录或软链别名的情况。Git 忽略不能代替扫描器自身的排除。

规格命名模式：`.superpowers/specs/YYYY-MM-DD-<topic>-<阶段后缀>.md`；计划模式：`.superpowers/plans/YYYY-MM-DD-<topic>.md`。

## 引用隔离

- 目录外不得引用 `.superpowers/` 或历史 `superpowers/` 下的任何具体文件，包括无日期、无扩展名、日志、JSON 和 diff；隐藏或被 Git 忽略的外部正文同样适用。
- 目录内部可互引；目录契约、占位模式与通用正则可写入规则说明。测试路径在隔离夹具中构造，不能以无日期文件名绕过检查。
- 知识库已有会话稿引用时，先把必要结论整理至正式知识来源；已有正式来源则改引，再移除会话稿引用。未经核实的结论仍标为待确认。
- 内部引用豁免不代表历史目录仍是合法的新产物落点。验收入口及规则见 [CONVENTIONS.md](../rules/CONVENTIONS.md#superpowers-ref-isolation)。

## 迁移

1. 清点当前工程的既有规格、计划及证据，核对目标重名、软链、Git 跟踪状态和工具路径身份；其他 checkout 单独处理。
2. 获得迁移授权后，将旧规格、计划分别移入新分类目录；目标存在时不覆盖。已在新根的执行证据无需搬迁。
3. 更新迁移文件的相对链接、计划身份和历史记录中的旧路径文字。历史哈希、时间和测试结果保留，不能重算后冒充当时验证；改写后的历史 diff 不作为原始补丁直接重放。
4. 同步路径契约、引用隔离、索引排除和行为测试；验证文件完整性、引用可达性及 Git 全局忽略。全局配置变更须获得用户明确授权。

## 与正式规约区分

| 类型 | 路径模式 | 职责 |
| --- | --- | --- |
| 会话规格、计划、证据 | 工程根 `.superpowers/` 的三个分类目录 | 本地协作材料，非正式 SSOT |
| 架构规约 spec-asd | `application/requirements/…/specs/spec-asd-*.md` 或 `{DOC_DIR}/specs/spec-asd-*.md` | 正式架构规约；[应用侧只读消费](../skills/sdx-design/references/central-spec-source.md) |
| legacy spec | `application/specs/spec-{yyMMdd}-*.md` | 历史规约输入，不随会话材料迁移 |

不得将普通 `specs/`、`plans/` 或 requirements 中的规约目录作为会话材料批量迁移；禁止引用 `ideas/**` 的既有约束继续适用。
