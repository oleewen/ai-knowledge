# ai-knowledge 实体 Profile v2

> **契约标识**：`ai-knowledge/v2`。本文件是本轮不兼容语义变更的独立版本入口；它不改变 OKF Core 的 `okf_version: 0.1`，也不代表内容版本已经发布或工具已经支持。

## 适用与变更

本 Profile 的语义正文由下列真源共同定义。修订后的共享规范面向 v2；既有消费库不因元库文档更新或安装了新 Agent 资源就自动完成迁移。

| 变更面 | v2 契约与真源 |
| --- | --- |
| 身份 | MS/API 从裸 ID 全局查重改为按 APP/MS 限定范围；完整身份、旧引用消歧见 [命名规范](naming-conventions.md#身份范围与限定引用) |
| 关系 | 新增 PD 单侧消费 SYS、反向派生；原归属、对标与其他双向边保持各自规则，见 [关系模型](entity-relations.md) |
| 布局与定位 | API 新布局区分 APP/MS；既有无冲突路径可保留，见 [布局契约](../references/knowledge-layout.md)。消费定位格式见 [联邦配置](federation-config.md) |
| 证据 | 来源与目标版本另记治理元数据，事实核验与历史可恢复性分开，见 [知识证据](knowledge-evidence.md) |
| 验收 | 结构、关系、引用、事实状态分报；迁移、注销及升级完成边界见 [统一校验](knowledge-validation.md) |

九个必填 frontmatter 字段的存储类型未变，但身份唯一域、关系目标和消费登记的语义已变化；不能因此宣称与所有旧工具兼容。未采用 v2 的库沿用其已确认的旧规则基线；无法确定旧基线时先核实，不猜测版本或执行迁移。

## 采用记录

目标库在获准迁移时，用 `{DOC_DIR}/governance/profile.md` 记录采用计划与结果；本次仅定义契约，不为四层模板创建采用记录。该文件属于治理元数据，不改变根 index 的 OKF frontmatter，也不向每个实体增加必填版本字段。

| 记录项 | 要求 |
| --- | --- |
| 契约标识 | `ai-knowledge/v2` |
| 旧基线 | 迁移前实际采用的规则版本、commit 或内容哈希；未知标待核实 |
| 目标规则基线 | 本 Profile 及所引用规则的可核对版本；未提交规则逐文件记录原始字节 SHA-256，不能只记分支名 |
| 工具覆盖 | 实际使用的工具版本、支持项与人工补核项；未支持的自动处理明确停止 |
| 迁移范围与结果 | 实体、引用、导航、消费定位和治理元数据的范围；关联验证结果及未闭合项 |
| 采用状态 | 待迁移 / 迁移中 / 已验证采用；只有适用检查全部完成才进入已验证采用 |

记录本身不能证明工具支持或迁移通过。正式写入新形态前先确认解析、查重、链接、索引和可视化的兼容策略；旧工具不支持的形态不得交其生成或覆盖。可人工完成的检查须保留依据及原工具结果，不静默忽略错误。

## 兼容与完成

1. 盘点本库旧格式与实际数据，核实 APP/MS 归属，列出局部重名、裸引用歧义、导航和消费登记影响。原始数据不自动改名、删除或重排。
2. 按已确认范围迁移。旧裸 MS/API 引用只有唯一可解析时才能补全；身份前缀变化按 [身份迁移与删除](knowledge-governance.md#身份迁移与删除) 处理。
3. 分别验证模板对齐、真实实体兼容和适用跨库约束，完成工具覆盖与人工补核。外库不可读或检查未执行时保留未闭环，不写“已验证采用”。
4. 采用记录与当前实际文件、规则基线一致后，才结束 Profile 迁移。`DESIGN.version` 仍由原发布/升级流程维护；采用 Profile 不触发 commit、push 或版本发布。

本轮代码尚未接入限定身份、消费定位、统一分项校验、治理元数据过滤与联邦并发恢复；跟进项见元仓 [TODO-LIST.md](../../TODO-LIST.md)。后续改变本 Profile 的不兼容语义，须另起版本入口并明确迁移关系，不能让已声明采用的基线静默改变。
