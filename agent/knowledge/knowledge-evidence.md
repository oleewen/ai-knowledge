# 知识证据登记

> **职责**：实体与章节的来源版本、核验状态和事实依赖记录。业务事实仍由所属实体或章节维护；本文不定义新的实体 ID，不保存来源正文，也不要求全量运行日志。

## 落点与粒度

记录存于目标库 `{DOC_DIR}/governance/evidence/`，纳入该库版本管理；是否提交仍遵用户授权。该目录属于治理元数据，不进入业务实体台账或实体关系图。

每份 Markdown 记录对应一个目标实体或章节及其一组来源版本。文件名采用 `EVID-000001.md` 等库内唯一记录键；编号仅用于定位本库证据，不是实体 ID，不承担跨库身份。新增来源版本或目标内容版本时建立新记录，旧记录保留原定位和哈希；核验、依赖及恢复状态可在原记录中更新，由 Git 保留变更历史。

提炼到 overview 时，登记预期目标实体或章节，并以 overview 路径和行标识记录当前缓冲位置；目标尚未写入则状态为“待落盘”，不填造目标版本。归档后登记实际目标版本，不能把 overview 自身当作原始事实依据。无新事实、无版本或状态变化时不重复建记录。

业务 knowledge 正文可用纯文本 `证据编号：EVID-000001` 定位本库记录，不写指向证据目录或库外文档的链接。来源路径等元数据仅在本目录登记，仍须遵守[业务引用规范](knowledge-reference-rules.md)。

## 最小记录模板

以下为 C 类元数据文件模板；一份记录只有一个 H1。多源时重复“来源”表，并使用该记录内的来源序号。

```markdown
# 证据 EVID-000001

| 记录项 | 值 |
| --- | --- |
| 目标身份 | 实体完整身份；章节填仓库定位与仓内路径#锚点 |
| 目标定位 | 目标库所属仓根相对路径#锚点 |
| 目标原始文件 SHA-256 | 实际字节哈希；待落盘填尚无 |
| 缓冲位置 | overview 路径与行标识；无则填无 |
| 前序证据编号 | 本库被接续的记录键；无则填无 |
| 核验状态 | 待核验 / 已核验 / 待复核 / 不成立 |
| 核验人及时间 | JSON 对象 name、at（带时区 ISO8601）；未核验填尚未核验 |
| 核验结论 | 支持范围、限制或待复核原因，不复制来源正文 |
| 处理状态 | 待落盘 / 已落盘 / 部分完成 / 已结束 |

## 来源 1

| 来源项 | 值 |
| --- | --- |
| 来源身份 | 已有实体完整身份；非实体用仓库定位与仓内路径#锚点；内联输入用可核对的会话消息定位 |
| 仓库定位 | JSON 对象 path、dir，可选 repository；内联输入填不适用 |
| 仓内路径与选取范围 | 相对仓根路径及章节锚点；内联输入标明消息与选取范围 |
| 原始字节 SHA-256 | 来源文件原始字节哈希；内联文本按原文 UTF-8 字节计算，不预先整理空白 |
| 已验证 Git commit | 确认该提交该路径内容匹配上述哈希后才填写；否则填未验证或无 |
| 采集时间 | ISO8601 时间 |
| 可恢复性 | 已核验可从指定 Git 版本恢复 / 当前原件可读但无持久版本保证 / 无法恢复 / 待核实 |
| 事实依赖 | 待建立 / 有效 / 解除待核实 / 已解除 |
| 解除依据 | 替代证据编号、独立复核结论或撤回目标的依据；未解除填无 |
```

实体完整身份按[命名规范](naming-conventions.md)填写；不得仅记录可能重名的本地 ID。锚点定位选择的实体或章节，SHA-256 固定整个来源文件的原始字节版本；文件其他部分变化也须复核影响，不能仅因锚点未变就认定事实未变。目录来源逐个登记实际支撑目标的文件，不以目录时间戳代替来源版本。

未提交来源允许使用。其哈希与核验结论须如实记录；当前 HEAD 不能冒充对应提交，无法核实的提交留空并注明状态。**哈希只能比对内容，不能还原内容。** 内联输入和未提交文件同样单列可恢复性，不能把“已核验”写成“历史可恢复”。

## 来源变更与依赖解除

核验状态回答“证据是否仍支持目标”，事实依赖回答“目标是否仍以该来源为依据”，两者分别维护。仅含历史定位的记录不自动构成有效依赖；标记“已解除”也不能替代真实核验。

目标新版本核验完成后，被替代记录可结束当前处理；仍有效的来源依赖须承接到新记录。记录版本切换或处理状态“已结束”不能让尚未解除的事实依赖消失。

目标实体或章节经授权删除时，记录最后实际核验版本、删除依据及依赖处理结果，在核验结论注明目标已删除；不伪造“删除后文件哈希”，不保留实体副本。历史正文只按原库 Git 历史恢复，证据元数据不承担正文备份。

1. 来源内容、身份或位置变化时，定位其影响的目标实体或章节，将相关记录标为“待复核”，保留原来源版本；不自动删除或改写派生知识。
2. 重新读取来源及目标，确认继续支持、需修订或不再成立。更新目标内容时新建版本记录；仅复核结论或状态变化可更新原记录。来源不可读或外库范围不明时保留待核实，不报告通过。
3. 删除来源前，逐项解除仍有效的事实依赖：迁移到已核验替代依据、完成独立复核，或经授权撤回相应目标事实。独立复核须登记实际复核依据和结论，不能只改状态。
4. 全部受影响依赖已处理且范围可核实时，旧记录可标“已解除”，作为历史证据保留。仅标“待复核”、将记录称为“历史”，或认为 Git 尚有旧文件，都不等于解除依赖；未知外库依赖阻止删除、身份迁移或注销闭环。

实体先变、章节后变时，实体新记录先登记实际版本；旧章节的证据仍指向其此前核验版本并标待复核。章节接续核验后登记实际采用的实体版本，不能仅因实体已更新就宣称章节已同步。确认书、会话与 TODO 可以承载交接，但不能替代证据登记。

## 写入与完成状态

证据记录与目标内容属于同一已授权批次。写前保留各待写文件及所用来源的版本指纹；写入前重新核对，变化则重读和复核，不覆盖他人编辑。先保存待落盘记录，再写目标；确认目标实际内容后补齐目标哈希和核验状态。只有目标与证据一致，才能清理相应 overview delta 或报告当前单元完成。

这不是跨文件事务。部分失败时停止后续写入，报告证据、目标和 overview 的实际状态；只在能证明文件仍为本轮写后版本时恢复本轮差异，否则保留现场并进入恢复。续接先重读文件与来源，不把旧确认或旧哈希视为新版本已核验。Git 合并、变基或集成后重新核对来源、目标及证据映射；未知或失败不得继承先前通过状态。

各技能现有授权、文件替换与恢复限制继续适用：[extract](../skills/docs-extract/references/workflow.md#落盘与失败)、[distill](../skills/docs-distill/references/gates.md#原子性)、[archive](../skills/docs-archive/references/gates.md)。`--dry-run` 不写证据或业务文件。

## 工具生命周期

[knowledge-evidence.py](../scripts/tools/knowledge-evidence.py) 只维护证据元数据；目标与 overview 正文仍由所属技能写入。命令与输入示例见[共享脚本](../scripts/README.md#证据与升级兼容)。默认预览，`--apply` 才写入；操作 ID、锁、指纹和恢复沿用[联邦写入协议](federation-config.md)。

| 动作 | 范围与结果 |
| --- | --- |
| `create` | 读取实际原始字节并计算来源哈希；分配库内编号，保存待落盘或已核验版本记录；指定 commit 时核对该提交该路径字节 |
| `update` | 显式更新核验、处理、依赖及恢复状态；目标从“尚无”首次绑定须匹配实际哈希；已有来源/目标版本和已验证 commit 不覆盖，变化须新建记录 |
| `refresh` | 检查已登记来源及目标，受影响记录标待复核；保留原哈希，业务正文不改 |
| `check` | 核对格式、身份、锚点、当前字节及指定 Git 恢复版本，逐项报告影响和恢复状态；FAIL/INCOMPLETE 均非零退出 |
| `resume` | 按原操作 ID 续办元数据步骤，核对写前/写后指纹，冲突保留现场；不续写目标或清理 overview |

机器可读表格仍使用上方中文字段，但枚举单元格只填一个准确值。`仓库定位` 示例为 `{"path":"${WORK_SPACE}/source-repo","dir":"docs"}`，路径以该来源仓根为起点；`dir` 用于实体身份解析，允许非实体资料位于库外的仓内路径。`核验人及时间` 示例为 `{"name":"核验人","at":"2026-11-07T12:00:00+08:00"}`。结论和解除依据由人提供；工具只能检查其存在与版本约束，不能证明结论真实。恢复依据可记核验结论，不拼入恢复状态枚举。

内联来源用 `repository: "不适用"`、`path: "message:会话/消息/范围"`；创建时 `inline_text` 按原文 UTF-8 计算哈希，转为已核验时须再次提供同版本原文。原文不写入证据或操作日志。后续报告只采用人工核验声明，不重新读取会话；可恢复性仍单列 UNVERIFIED，哈希不是备份。

旧自由文本仓库/核验人字段须先人工规范化；工具不猜定位、不改旧字节哈希。前序记录缺失、成环或属于不同目标身份均待核实。同一目标存在未核实的当前记录时，不用另一条已核验记录覆盖疑点。已结束记录仍按各来源的事实依赖阻塞删除/注销；解除须登记核验人及具体依据。

记录扫描仅覆盖本库已登记证据；未登记来源、未读取外库、业务语义变化均不能自动发现。元数据操作完成与事实单元验收分别报告，最终仍需 `check` 及所属流程的正文验收。
