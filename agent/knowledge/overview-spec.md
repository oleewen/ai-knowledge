# overview 缓冲表规范

> **职责**：overview 的表行结构、层级内容边界、归档章节与共用增量语义。
> **边界**：文件路径见 [knowledge-layout.md](../references/knowledge-layout.md#overview)；各技能的输入、写入与回写方式见[写入能力](#写入能力)；文件分型见 [okf-spec.md](okf-spec.md#6-叙事文件处理规则)。

## 表行与内容边界

- overview 为叙事缓冲区，不替代实体 `{ID}.md`。
- 表按「主标题 / 副标题 / 归档列」维护。**实际行序与锚点真源**是目标层 overview 模板及同层五视角 README 表行；必须逐行读取，不能用本文摘要替代。
- 第三列只存待归档 delta。公司只收 SLN 级共性；应用只收本应用实现要点。
- 元库 overview 与 README 只列必有章；按需章由安装后使用方添加，不补空文件。ADR 留在 `adr/`，不进 `chapters/`。

## 第三列增量语义

第三列只存尚待归档的 delta，不替代目标知识正文。候选进入第三列不表示已归档，也不自动成为已确认事实。

来源版本、候选与派生实体/章节的关联另按 [知识证据契约](knowledge-evidence.md) 保存，不把来源路径、指纹或运行日志堆入第三列。来源变化时先标待复核；归档成功须同时核对目标与证据关联，再回写 delta。

### 覆盖与等价判定

1. 比对表行副标题链接的锚点小节；不可读时回退主标题整章。两者均不可读时，覆盖关系待核实，不能推断未覆盖。
2. 目标章节或相关实体已实质覆盖、事实一致而仅表述不同，均视为已覆盖，不重复提炼全文。
3. 旧第三列用于核对待归档工作，不是新事实来源，也不能单独证明目标知识正文已覆盖。来源正文用于提炼事实，不能替代目标覆盖证据。

### A/U/D

| 标记 | 共用含义 |
| --- | --- |
| `[A]` | 来源有新增要点，目标知识正文尚未覆盖 |
| `[U]` | 已有要点发生变化；默认只写变更 delta，无法拆分时先确认「delta / 整段重摘要」 |
| `[D]` | 有明确废止依据或用户针对具体要点的删除确认，形成待归档的删除说明；来源未提及、关键词未命中都不是删除依据 |
| `—` | 无待归档 delta；不代表目标正文中的旧事实已被删除 |

提炼和归档均须核对 `[D]` 的依据；标记本身或一般流程授权不能代替具体删除决定。依据未核实时保持未决，不生成可执行删除说明、不删除目标正文，也不清除已有待核实 delta。

`[D]` 不自动删除实体或级联删除上层摘要；涉及实体及有效依赖时，先满足 [身份迁移与删除](knowledge-governance.md#身份迁移与删除) 的条件。保留历史证据关联不等于保留有效业务依赖。

本节定义数据含义，不统一各技能的写入动作。全量替换、命中批次保留旧项、归档成功后的回写分别由对应技能定义；“已覆盖”或“无命中”不能单独授权清空第三列。

## 系统模板章节

必有章与 `system/knowledge/*/chapters/`、同层 README 章表一致；下表仅给模板结构，处理时仍读取目标表行。

| 视角 | 必有章顺序 | 安装后按需添加 |
| --- | --- | --- |
| 业务 | 概述、术语、能力地图 | 域划分、流程、业务规则与策略 |
| 产品 | 概述、产品架构、信息架构、产品功能、用户旅程与场景 | 版本管理与发布、产品运营支撑、多端策略 |
| 应用 | 系统概述、应用架构、领域模型、服务设计、集成架构 | 领域能力、服务间交互、接口管理、多租户多环境 |
| 技术 | 中间件、性能扩展、高可用 | 技术概述、基础设施、可观测性 |
| 数据 | 数据模型、数据存储 | 数据概述、数据分析、数据流转 |

## 其他层模板章节

| 层 | 章节约束 |
| --- | --- |
| 应用 | 业务/产品不建章节，README 仅作纯 ID 入口；应用：接口管理；技术：中间件、性能扩展；数据：数据模型。归档进本层 chapters |
| 解决方案 | 业务范围、应用与集成、数据主权、技术选型 |
| 公司 | 以 `company/knowledge/overview/` 模板与同层 README 为准 |
