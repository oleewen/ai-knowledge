# 产品架构

## 产品概述

本节阐明产品定位、用户、竞争与路线，为功能架构、旅程与度量提供统一语境，并与业务架构可对齐。

### 产品定位与价值主张

**应写内容**：产品解决的核心问题与差异化价值；与商业模式、业务能力的对应关系；非目标或暂不承诺的能力边界。语言需可被销售、研发与运营一致引用。

**产出建议**：一句话定位 + 价值主张要点列表；可选「我们是什么 / 不是什么」对照。

### 目标用户与用户画像（Persona）

**应写内容**：主要与次要用户细分；每类 Persona 的目标、痛点、使用情境、决策因素与技术素养；与业务侧客群定义一致。避免虚构无验证的画像。

**产出建议**：Persona 卡片或表（含名称、场景、关键需求）；与获客渠道、定价策略的交叉引用。

### 竞品分析

**应写内容**：直接/间接竞品与替代方案；功能、体验、定价、生态对比；可借鉴点与防御点。分析维度与更新频率说明。

**产出建议**：竞品对比矩阵或一页摘要；信息来源与最后评审日期。

### 产品路线图（Roadmap）

**应写内容**：按季度或主题的阶段目标、交付物与依赖；与业务 OKR、技术演进的衔接；已承诺与探索项区分。变更记录与沟通节奏。

**产出建议**：时间线或 Now/Next/Later 视图；与版本、里程碑编号对应。

## 产品功能架构

本节将价值主张拆解为可交付的功能模块与优先级，支撑排期与范围治理。

### 功能模块全景图（Feature Map）

**应写内容**：模块划分与层级（域—模块—功能）；模块与业务能力、应用服务的映射关系；模块间依赖与数据流摘要。

**产出建议**：Feature Map 图或思维导图；与 PRD/需求池 ID 可追溯。

### 各模块功能清单（按版本 / 里程碑）

**应写内容**：每模块下的功能点、状态（已上线/开发中/规划中）、负责人；与版本或 Epic 的绑定；验收标准入口。

**产出建议**：功能清单表或需求管理工具视图；版本字段统一。

### 功能优先级矩阵（MoSCoW / RICE）

**应写内容**：优先级方法论选型；评分维度与权重；与资源、风险、依赖的权衡记录。争议项的升级路径。

**产出建议**：优先级矩阵或打分表；复盘时调整规则说明。

### MVP 定义与迭代规划

**应写内容**：MVP 范围、成功标准与退出条件；迭代节奏（双周/月度）与发布火车；技术债与体验债的显式纳入或排除。

**产出建议**：MVP 范围列表；迭代日历或里程碑表。

## 用户旅程与场景

本节从用户视角串联触点与情绪，驱动故事与用例沉淀，并与信息架构、埋点一致。

### 核心用户旅程地图（User Journey Map）

**应写内容**：主旅程阶段、用户目标、触点、情绪曲线、痛点与机会点；与业务关键流程 L0–L2 对应。多端旅程可分支说明。

**产出建议**：旅程地图（工具图或一页描述）；优先级旅程与次要旅程标注。

### 用户故事地图（User Story Map）

**应写内容**：横向用户活动、纵向发布切片；故事粒度与 INVEST 约定；与路线图、MVP 的对应。

**产出建议**：故事地图图或表；与 Backlog 的链接方式。

### 关键场景用例（Use Case）

**应写内容**：参与者、前置/后置条件、主成功路径与扩展路径；与业务规则、接口契约可追溯。复杂场景拆分子用例。

**产出建议**：用例说明或 UML 用例图摘要；编号规则与模板。

### 用户故事清单

**应写内容**：作为/我想要/以便格式或等价结构；验收标准（Given/When/Then）；依赖与拆分原则。与测试用例、埋点可挂钩。

**产出建议**：故事清单（工具导出或表）；与 Epic/Feature 的层级关系。

## 信息架构

本节定义导航、层级与内容模型，支撑可发现性与一致心智模型。

### 导航结构（站点地图 / 菜单树）

**应写内容**：全局与局部导航层级；入口可见性规则（角色、权限、端）；与 URL/路由命名约定。避免深层迷宫式菜单。

**产出建议**：站点地图或菜单树图；与权限矩阵交叉引用。

### 页面层级与信息组织

**应写内容**：列表—详情—编辑等模式；面包屑与返回行为；关键任务路径不超过 N 步等体验约束。

**产出建议**：关键路径示意图；页面类型模板说明。

### 内容模型

**应写内容**：核心内容类型、字段、关系与生命周期（草稿/发布/下线）；与 CMS、数据字典的对应；多语言与 SEO 字段（如适用）。

**产出建议**：内容类型清单或 ER 草图；与 API/管理后台字段对齐。

## 交互与体验设计

本节统一视觉与交互语言，保证核心流程可理解、可完成、可访问。

### 设计规范 / Design System

**应写内容**：色彩、字体、间距、组件库与变体；品牌与无障碍约束；与设计 Token、代码组件库的同步机制。

**产出建议**：Design System 文档或 Storybook 链接；版本与破坏性变更说明。

### 核心页面原型与交互说明

**应写内容**：高保真/低保真原型范围；关键页面状态（空、加载、错误、权限不足）；与设计稿、前端实现的评审流程。

**产出建议**：原型链接或导出；页面—组件—状态索引。

### 关键交互流程图

**应写内容**：任务级交互序列（含分支与校验反馈）；与异常路径、文案一致；微交互与动效的使用边界。

**产出建议**：流程图或交互说明文档；与用例、埋点事件对齐。

### 无障碍（Accessibility）设计

**应写内容**：目标标准（如 WCAG 等级）；键盘、读屏、对比度、焦点顺序要求；组件无障碍验收清单。

**产出建议**：无障碍检查表；关键页面的审计记录入口。

## 多端策略

本节明确各端覆盖范围与差异，避免功能与体验碎片化。

### 端的覆盖（Web / App / 小程序 / H5 / 桌面端）

**应写内容**：各端目标用户与使用场景；首发与维护策略；技术栈与发布渠道摘要（可链路至应用架构）。

**产出建议**：端—场景—优先级表；下线或冻结端的说明。

### 各端功能差异矩阵

**应写内容**：功能在行（功能）列（端）矩阵中的可用性、限制与原因；与账号体系、支付等跨端一致性的说明。

**产出建议**：差异矩阵；已知限制与用户沟通文案。

### 响应式 / 自适应策略

**应写内容**：断点、布局策略与组件行为；移动端优先或桌面优先的选择；与 Design System 栅格一致。

**产出建议**：断点与布局规范；关键模板截图或说明。

## 产品运营支撑

本节沉淀运营、内容、触达与反馈所需的产品能力，支撑增长与留存。

### 运营后台功能清单

**应写内容**：后台模块（用户、订单、内容、配置等）、权限模型与审计；与业务运营 SOP 的对应。敏感操作的二次确认与日志。

**产出建议**：后台功能清单表；角色—权限说明。

### 内容管理（CMS）

**应写内容**：编辑工作流、审核、定时发布、回滚；多媒体与多环境预览；与内容模型、CDN 发布的关系。

**产出建议**：CMS 能力说明；编辑与开发者职责边界。

### 消息 / 通知体系

**应写内容**：站内信、推送、短信、邮件等通道与模板；触达频率、静默时段与用户偏好；与营销合规一致。

**产出建议**：消息类型与模板清单；退订与同意管理说明。

### 活动 / 营销 / 优惠券体系

**应写内容**：活动类型、规则引擎边界、风控与反作弊摘要；券种、面额、叠加规则与财务对账入口。与业务规则编号一致。

**产出建议**：活动与券体系能力表；异常与补偿流程索引。

### 用户反馈与工单

**应写内容**：反馈入口、分类、SLA 与升级路径；与客服系统、缺陷管理的对接；用户可见的处理状态。

**产出建议**：反馈—工单流程说明；指标（响应时长、解决率）入口。

## 产品度量

本节连接产品行为与数据闭环，支撑实验与迭代决策。

### 北极星指标

**应写内容**：单一北极星及其与用户价值、商业结果的逻辑链；反指标或护栏指标；评审与调整节奏。

**产出建议**：北极星定义一页；与业务 KPI 对齐说明。

### 核心数据指标体系

**应写内容**：AARRR 或等价框架下的核心指标；定义、口径、责任人；与数仓/报表主题一致。

**产出建议**：指标字典摘要或链接；与数据架构指标治理交叉引用。

### 埋点方案与事件清单

**应写内容**：事件命名、公共属性、采样与隐私；与页面、组件、关键旅程的映射；版本化与兼容性。

**产出建议**：埋点文档或事件目录；与数据架构埋点规范一致。

### A/B 测试框架

**应写内容**：分流策略、样本量、统计方法与伦理边界；实验平台与发布、特性开关的配合；结论沉淀与全量标准。

**产出建议**：实验模板或规范；历史实验索引。

### 用户行为分析

**应写内容**：漏斗、留存、路径等分析场景与工具；与产品评审例会的结合方式；隐私与聚合展示原则。

**产出建议**：核心看板列表；分析问题 backlog。

## 版本管理与发布

本节统一版本语义、发布说明与灰度策略，与工程发布及特性开关协同。

### 版本命名规范

**应写内容**：语义化版本或日历版本规则；预发布、热修复标识；与营销版本号、应用商店版本的关系。

**产出建议**：版本规范一页；示例与反例。

### 发布记录（Release Notes）

**应写内容**：面向用户与面向内部的变更说明；已知问题与升级指引；多语言与渠道差异。归档位置与检索方式。

**产出建议**：CHANGELOG 或发布说明模板；与工单、合并请求的追溯。

### 灰度发布策略

**应写内容**：灰度维度（用户、地域、百分比）、监控指标与回滚条件；与 DevOps 发布策略、技术架构一致。

**产出建议**：灰度 Runbook 摘要；关键版本检查表。

### 功能开关管理

**应写内容**：开关类型、命名、生命周期与权限；与产品实验、Kill Switch 的边界；默认安全策略。

**产出建议**：开关登记规范；与应用架构特性开关交叉引用。
