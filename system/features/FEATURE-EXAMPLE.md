## 1. 背景目标

### 1.1 需求背景

- 关联需求分析：`system/analysis/ANALYSIS-EXAMPLE.md`
- 本系统要收口高频链路的状态口径，并给出运营可单入口定位的能力。

### 1.2 需求目标

| 目标编号 | 目标描述 |
| -------- | -------- |
| G1 | 高频链路状态可按同一口径解释 |
| G2 | 运营可依据本系统单入口呈现的证据判断卡点与下一步协作方 |

### 1.3 范围约束

#### 范围与边界

- 范围内：本系统高频链路的状态词典与定位入口
- 范围外：跨系统编排与统一视图

#### 假设与约束

- 上游 §6.1 的「里程碑1」覆盖高频链路最小闭环

#### 研究与分析

- 状态歧义来自多应用并行查询；本特性只收本系统入口

## 2. 功能需求

### 概览

本样例上游 §6.1 的里程碑列写的是「里程碑1」，此处原样抄入。技能常态写法是 `M{n}（短名）`。

| 需求编号 | 需求名称 | 需求概要 | 优先级 | 所属模块 | 所属里程碑 | 关联目标 |
| -------- | -------- | -------- | ------ | -------- | ---------- | -------- |
| FR-001 | 统一状态口径与辅助异常定位 | 统一状态解释，呈现链路证据供运营判断卡点与协作方 | P0 | 状态口径与异常定位 | 里程碑1 | G1、G2 |

### FR-001: 统一状态口径与辅助异常定位

**描述**：运营查看高频链路对象时，本系统统一状态解释，并在同一入口呈现各应用的状态、关键时间点、责任环节与协作方。运营据此判断卡点；本轮不自动判定卡点。

**输入**：业务对象标识，以及该对象已进入高频链路；本系统内各应用可提供的状态、关键时间点及对应责任环节与协作方。缺失信息按 BR-003 处理。

**处理逻辑**：

| 规则编号 | 规则名称 | 触发条件 | 执行逻辑 |
| -------- | -------- | -------- | -------- |
| BR-001 | 口径统一 | 状态已被词典覆盖且可明确映射 | 按本系统状态词典解释；不得用统一解释掩盖相互冲突的状态证据 |
| BR-002 | 定位证据呈现 | 运营查询高频链路对象 | 在同一入口展示各应用状态、关键时间点、责任环节与协作方，标明所属应用和环节，供运营判断卡点 |
| BR-003 | 证据不足提示 | 状态、时间点、责任环节或协作方信息缺失，以及状态冲突、词典未覆盖 | 保留并展示已有信息，逐项标明缺失、冲突或待补内容，提示「证据不足，需人工核实」；不推断缺失内容，不给出确定卡点结论 |

**业务对象**：

| 业务对象 | 操作类型 | 变更说明 | 一致性 / 时效期望 |
| -------- | -------- | -------- | ----------------- |
| 链路状态 | 变更 | 展示口径收成一条 | 查询时可见 |
| 链路定位证据 | 查询 | 汇集状态、时间点、责任环节与协作方，不改各应用原处理规则 | 查询时呈现已有信息与缺口 |

**输出**：可明确映射的统一状态解释，以及按应用和环节关联的定位证据；证据不足时附缺口与人工核实提示。卡点由运营判断。

**异常与边界**：证据不足不阻止已有信息展示，按 BR-003 提示；本轮仅覆盖本系统内的辅助判断，不增加跨系统编排、跨系统统一视图或自动诊断。

**验收标准**：

1. 对证据齐全的典型异常样例，单入口完整呈现各应用状态、关键时间点、责任环节与协作方；运营可据此判断卡点及下一步协作方，与样例预期一致。
2. 对词典已覆盖且可明确映射的高频状态，统一解释与词典一致；状态冲突不得被静默归并成确定状态。
3. 分别验证状态、时间点、责任环节或协作方信息缺失，以及状态冲突、词典未覆盖的样例：已有信息仍可见，缺口或冲突标注准确，并提示「证据不足，需人工核实」；不补造缺失内容或自动输出确定卡点。

## 4. 交付计划

### 4.1 MVP 总览

| MVP 阶段 | 核心目标 | 包含需求 | 交付价值 | 预估工期 | 前置依赖 |
| -------- | -------- | -------- | -------- | -------- | -------- |
| MVP1（定位入口） | 高频链路状态统一并可单入口辅助定位 | FR-001 | 运营据证据判断卡点，证据不足可识别 | 待共拟 | 无前置 MVP；业务依赖见 §5.1 |

### 4.2 MVP 详细规划

#### MVP1（定位入口）

**目标**：高频链路状态词典与定位入口可验收。

**范围**：

- 功能需求：FR-001
- 涉及业务流程 / 能力域：状态口径与辅助异常定位
- 涉及业务对象：链路状态、链路定位证据

**验收标准**：

按 FR-001 的三项验收标准执行，覆盖证据齐全与证据不足样例；不以自动判定卡点作为验收要求。

上述标准验证功能行为；里程碑退出仍须满足上游 ANALYSIS §6.1 的「高频状态无未决歧义」。证据不足或冲突提示测试通过，不豁免交付范围内的该退出条件。

**依赖项**：

- 与运营值班口径在试点前对齐
- 试点前与运营确认典型异常样例、预期卡点及协作方；证据来源与可用性见 §5.1。
